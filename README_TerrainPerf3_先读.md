# ORBIS TerrainPerf3 · 2D World / Zone 4×4

**基于指定的 TerrainPerf2 Zone4×4 CivilizationFirst 完整包修改。不是另起一个不相干项目，也不是只有补丁。**

本分支将权威模拟迁到 2D 矩形地图：每个 Tile 有独立数据，1 Zone = 4×4 = 16 Tiles。3D 星球由同一世界数据生成，只用于摄影和展示，不再推进第二套文明模拟。

## 打开与启动

1. 完整解压，Unity Hub → Add / 从磁盘添加项目，选择包含 `Assets`、`Packages`、`ProjectSettings` 的文件夹。不要只复制 Assets 到其他项目。
2. 使用基础包对应的 **Unity 6000.0.47f1、Built-in Render Pipeline**。本次不升级 Unity、不引入 URP/HDRP、不增加外部包依赖。首次导入仍由本机 Unity 完成。
3. 主场景为 `Assets/ORBIS/Scenes/Orbis2DWorld.unity`。首次初始化与 Windows 构建入口都已改为这个场景。也可点 `Tools → ORBIS → 2D World → 1 Open 2D main scene`，再按 Play。
4. 默认生成 `512×256 = 131,072 Tiles / 8,192 Zones` 的世界，并尝试播种 4 个文明。输入新种子可重新生成；“生成新世界”会替换当前运行中的世界，请先保存。

**当前交付是完整源码原型项目，不是经 Unity 实机验收的成品或已编译 EXE。此环境没有 Unity Editor/C# 运行时，未执行 Unity 编译、Play Mode、GPU 着色器编译、帧率或真实截图测试。** 已执行的离线检查与未执行的测试严格分列，见 `Documentation/TerrainPerf3/验收与已知限制.md`。

## 已写入的功能

| 模块 | 当前实现 |
|---|---|
| 2D 主地图 | 正交 RTS 上帝视角，矩形像素 Tile，整数像素缩放，拖动/WASD 平移，Tile/Zone 选择与网格 |
| 世界数据 | 独立海拔、填洼/湖面高度、水体、气候、生物群系、肥力、归属、设施、人口和排水关系 |
| 世界生成 | 大陆、群岛、超级大陆、内海 4 套形状预设，周期噪声，20 档地形高度 |
| 水文 | 深海、中海、浅海、淡水湖、淡水河流；按父节点先于子节点的顺序排水和汇流 |
| 气候 | 12 个月合成温度/降水、地形抬升与背风影响、海陆差异、季节变化、30 类 Köppen 分类 |
| 文明原型 | 播种文明、首都、人口与粮食、相邻 Zone 扩张、迁移人口、农田/道路/桥梁、陆路路径查看 |
| 编辑 | 1 Tile、1 Zone、3×3、9×9 高度笔刷；手动重算排水/气候，无实时板块运动 |
| 星球 | 同一高度/水体/归属数据映射回既有闭合球面网格，保留原海洋/大气/夜侧渲染路径；摄影暂停模拟 |
| 文件 | 独立 `.orbis` 存档、SHA-256 校验、备份，16-bit 灰度高度图导入/导出、无 UI 截图请求 |

## 操作

拖动地图平移，滚轮按整数倍率缩放。WASD/方向键平移，`Home` 全景，`F` 聚焦已选 Tile，`G` 网格，`Space` 暂停，`M` 在 2D 与星球间切换。键盘快捷键作用于已聚焦的地图区域；编辑文本时不抢占按键。

左侧“操作工具”选择建国、扩张、地形笔刷或设施。先点击本国地块选择活动文明，再对相邻无主 Zone 扩张。首都起始 500 人只存于一个 Tile，不会在 16 格复制。扩张消耗 60 粮食，并从已有聚落转移一部分人口。农田/道路消耗 15 粮食，桥梁消耗 40 粮食。

星球模式拖动环绕、滚轮调整距离，滑块改变阳光方向。文明时钟暂停，水面和云层的视觉动画可继续。再次 `M` 回到原来的 2D 世界。点击“无 UI 截图”请求 PNG；实际文件生成由 Unity/操作系统完成，请在存档文件夹确认。

## 高度规则

海平面 0m 不算陆地档位。L01–L10 上界依次为 100、200…1000m；L11–L20 上界为 **1120、1280、1480、1720、2000、2320、2680、3080、3520、4000m**。陆地生成/笔刷采用这些预设高度；海床保留 −4000..0m 整数。

深海：海床低于 −1000m；中海：−1000m 到低于 −200m；浅海：−200..0m。湖泊和河流是单独类型，不靠颜色或海拔正负冒充。以上水深分档是本项目游戏规则，不是声称采用全球通用的海洋学分带。

## 存档与高度图

完整状态保存在 `Application.persistentDataPath/orbis-flat-world-v1.orbis`。按钮可打开该目录。保存旧文件时尽可能保留 `.bak`。原 V4 JSON 不会覆盖，也不会被当成新 Tile 存档自动加载。

灰度高度图要求 2:1、宽度 64–1024、宽高均可被 4 整除。16-bit PNG 推荐；黑色 −4000m，白色 +4000m，北在图像上方。导入会重新生成水文/气候/文明；它不是完整存档导入。附有可导入示例 `Examples/FlatWorld/reference-continents-height16.png`，以及明确标为非 Unity 截图的离线参考图。

## 检查入口

`Tools → ORBIS → 2D World → 2 Run core data validation` 执行实际 C# 核心用例；`3 Compile current-API map and globe shaders` 检查当前图形 API 的着色器。`4 Build Windows player` 需要本机安装 Windows Build Support。

旧场景 `OrbisDemo.unity` 与旧版渲染/文档仍保留。旧验证报告只说明旧版本，**不能作为 TerrainPerf3 通过编译或实测的证据**。

## 重要边界

柯本是分类器，不是天气预报引擎。本分支气候是为文明玩法服务的合成季节模型，未做真实气象数据校准；摄影云层是月均气候驱动的展示快照，不运行原高频天气求解。没有把战争军队、逐人 AI、海军运输、完整贸易外交、撤销栈伪装成已完成内容。

建议先以默认尺寸验证核心循环与两种视图，再做扩展。详细设计、来源对照、修复审查、测试说明均在 `Documentation/TerrainPerf3/`。
