# ORBIS V4.2 · 分层动态云雨接入版

**基线：用户提供的 `ORBIS_Unity_V4_1_2_AtmosphereTransit(1).zip`。**  
**工程：Unity 6000.0.47f1 / Built-in Render Pipeline。交付日期：2026-09-11。**

> 本包已经修改实际 Unity 工程代码，不是只有设计建议。当前状态为“已接入源码、通过独立数值与源码检查，等待 Unity 导入与实机验收”。本环境没有连接到 Unity Editor；没有执行 C# 编译、Unity Shader 编译、Play Mode 画面验收、声音试听或设备性能测试。不得把本包理解为已经通过这些环节的发布成品。

## 1. 打开与体验

解压后，在 Unity Hub 中添加本文件所在的工程目录——该目录内应直接看到 `Assets`、`Packages`、`ProjectSettings`。使用原工程的 Unity 6 Built-in 环境，打开 `Assets/ORBIS/Scenes/OrbisDemo.unity`，让 Editor 完成导入后进入 Play。

系统沿用原来的运行时场景装配方式：`OrbisDemo.Awake()` 会自动挂接天气特效，不需要手动创建下雨对象或拖入脚本。先查看 Console 是否有编译错误。

在左侧 **“V4.2 · 全球云雨与雷暴”** 面板中：

1. 保持“动态天气”“云层”“云影”开启，选择“自然地貌”图层。按“寻找降雨”定位当前实际下雨的地块；当前没有降雨时，按钮会明确提示，不会凭空生成一场雨。
2. 按“雨中近景”进入选中地点附近的低空视角。雨滴读取该处降水，湿地读取同一地表水膜状态。移动到晴区后，局部雨滴应逐渐消失；已经湿润的地面不会瞬间恢复干燥。
3. 按“寻找雷暴”定位当前成熟对流。闪电先发生，雷声按照同一事件到观察者的距离延迟播放；高轨和展开地图不播放近地雨滴与雷声。

“雨滴与水花”“闪电”“雨声与雷声”“湿润材质”是独立显示/声音开关，不会因此凭空改变大气中的水量。天气是否继续推进由原来的“动态天气”与暂停控制。

**对流试验不是正常天气的必要开关。** 选择一个地区后，按“对流试验：扰动选区温湿条件”，会提高近地温度、降低部分中层温度并从本地地表水库转移水汽。它不直接设置云水、降水或闪电；是否发展成雷暴仍由后续演化决定。该操作会改变当前世界，建议先保存。

> 根目录旧 README 和 `Preview/AtmosphereTransit.html` 都被保留。HTML 仍然是 V4.1.2 大气穿越参考，不包含本次 Unity V4.2 天气系统，不能拿它验收这次新增功能。

## 2. 本次实际接入了什么

| 需求 | 工程中的实现 | 边界 |
|---|---|---|
| 云不再固定在原位 | 球面相邻网格之间输运六类水；云水本身迁移，不只滚动 Shader UV | 上风通量会有数值扩散；气候条件允许一些地区长期多云，但没有永久地理云遮罩 |
| 云出现、消散、疏密变化 | 饱和调整、蒸发、液冰相转换改变真实云水路径 | 是实时简化模型，未校准为气象预报模式 |
| 高、中、低云 | 12 层温湿结构和独立分层风；GPU 三维纹理按高度读取液水、冰与云量 | 不是三个固定云壳；薄层云的最终清晰度仍需 GPU 验收 |
| 积云发展与积雨云 | 简化气块 CAPE/CIN/LCL、上升气流、垂直交换、发展/成熟/消散诊断 | 没有完整解析云砧、超调云顶或风暴内小尺度湍流的模型 |
| 降雨与冷池 | 云液水转雨、碰并、冰雪/霰转换、落水、雨蒸发冷却和冷池扩散 | 微物理为本工程的简化率式，非 WRF/ClimaAtmos 的完整实现 |
| 打雷闪电 | 混合相云冰、霰与上升气流累计电荷代理；成熟雷暴触发事件 | 提供云内/云地视觉分支；没有完整电场求解或专门云间电荷连接求解 |
| 云影 | 视线云和太阳方向云影调用同一个三维密度函数 | 延用太阳方向光学深度缓存；低采样可能漏掉极薄云层 |
| 雨滴与落地水花 | 相机附近的池化雨线与地面环形水花；雨强来自当前位置 | 不包含远景体积雨幡、屋顶遮挡或任意建筑碰撞检测 |
| 雨后湿润 | 表面水膜随落雨累积，蒸发/入渗后衰减；材质变暗、增强高光与局部涟漪 | 接入 ORBIS 自有 Surface Shader，不会自动改造外部标准材质 |
| 一套天气贯通视图 | 球体、展开图、近地视角与特效共享相同大气柱 | 展开地图显示云和云内光照，不绘制近地雨线几何 |

云的宏观存在性来自 `qc + qi`，体积噪声只切出小尺度形状。没有云水时，Shader 密度返回零。旧的解析风暴位置模板只参与初始化阶段，不再持续在背后固定或人工巡回生成云区。

## 3. 核心数据与推进

全球网格保留原项目的 **3,456 个四边形地块**，每块有 12 层，合计 **41,472 个大气单元**。边界高度为：

```text
0, 300, 800, 1500, 2000, 3000, 4000,
5000, 6000, 8000, 10000, 12000, 16000 m
```

每层的 `Water[0..5]` 分别是水汽、云液水、云冰、雨、雪、霰的**层水路径，单位 kg/m²**。不是未经加权的质量混合比。需要混合比时再除以该层参考干空气质量 `AirMass`。

```text
地表/旧气候边界条件
→ 切向风、压力异常、低层辐合和地形抬升
→ 保正值、面积加权的水平有限体积输运
→ 气块不稳定度与分层垂直交换
→ 地表蒸发 / 饱和凝结 / 潜热
→ 液水、冰、雨、雪、霰之间的转化
→ 降水落地 / 蒸发冷却 / 冷池边缘抬升
→ 同一物理状态输出云、云影、雨滴、雷暴、湿润材质
```

气压包含参考静力垂直剖面和水平可演化异常；不是完整三维可压缩流体求解。热力边界继续接受原来的温度、季节、海陆与环流信息。凝结/蒸发潜热及云遮蔽会反馈到大气柱温度，但旧世界的海洋、土壤和文明气候接口仍为近似耦合，未建立整个世界的严格能量闭环。

### 尺度约定——不要混用

| 量 | 本包约定 |
|---|---|
| 模拟时间步 | 固定 0.1 天气秒，防止大帧直接冲垮微物理 |
| 微物理时间 | 每天气秒推进 45 个物理秒，用于游戏时间压缩 |
| 水汽/水凝物水平速度 | 弧度/天气秒；为可观察的游戏尺度运动 |
| 上升、降水沉降 | 微物理中以 m/s 表达 |
| GPU 云高 | 相对当地地形，`HeightScale = 0.000006 R/m` |
| 光学大气尺度 | 保留 V4.1.2 的光学参数换算；不与天气显示高度强行混同 |
| 雨滴大小/视觉下落速度 | 艺术化放大，不能按真实毫米雨滴或微物理沉降速度解释 |
| 雨强 | 地面实际落水量换算为 mm/h，不是随机动画强度 |

这是为小尺寸行星世界做的实时近似，不是接入真实地球卫星云图、实时天气 API 或数值天气预报数据。风速、垂直高度与视觉比例经过游戏化处理，不能用其输出做现实天气判断。

## 4. 云与地表共享的 GPU 接口

`OrbisWeatherField` 保留旧的二维兼容天气图，同时新增：

- `_AtmosLayers`：128 × 64 × 12，编码云液水密度、云冰密度、云量、垂直速度。
- `_AtmosLayerWind`：128 × 64 × 12，每层切向风。
- `_WeatherEffects`：256 × 128，编码降雨强度、湿润程度、风暴阶段、降雪强度。

球面模拟本身没有经纬度极点奇异性。渲染图采用经度重复、纬度钳制，顶底极环做平均。不同高度通过非均匀层中心映射读取，避免把一张二维云图一直拉到高空。细节噪声保留有界双相流动，不累计无限增长的位移。

体积云采样预算更新为 32 / 48 / 64 / 64 步；大气为 16 / 24 / 32 / 48 步。所有嵌套体积采样循环保持显式 `[loop]` 和显式 LOD，保留之前针对无法展开循环问题的防护。此项是源码约束，不是 Shader 编译成功证明。

## 5. 雨、雷与湿地的实现细节

雨滴使用固定容量动态网格：900 条雨线、160 个落地环，不在每帧实例化大量 GameObject。雨和水花位置保持在行星局部空间，行星自转不会让它们脱离地面。近地雨强读取地面通量；更高处读取所在层雨水，不把地面下雨错误解释为整个高空都下雨。

雷电使用最多 4 组复用折线和分支。事件来自气象核心；视觉队列有上限，切换世界不会重播旧闪电。光照脉冲同时写入地表和体积云着色器。雷声使用最多 8 个复用音源，传播速度随温度做近似修正。程序生成单声道雨声与雷声，无外部音频下载或授权依赖；它们是可替换的占位音色，不是已试听的最终音效。`OrbisWeatherEffects.outputMixer` 可接已有 AudioMixerGroup。

地表 `SurfaceWater` 是水库，`Film` 是其中用于湿地视觉的水膜子集，不能重复计入总水量。入渗减少 Film 但不删除 SurfaceWater。湿润程度为连续值，不是“下雨开、晴天关”的瞬时切换。

## 6. 存档与保留功能

保留地形、河网、水体、文明、地理分区、导入地图、地图展开、大气穿越与此前源码归属说明。没有替换为 URP/HDRP，也没有引入新的大型包或字体文件。

V4.2 存档增加分层水量、温度、风、地表水、水膜、冷池、压力异常、上升气流、阵风抬升、电荷、冷却时间、风暴阶段与随机状态。老存档没有分层数据时，保留原世界并初始化新的分层天气，不能恢复它从来没有保存过的三维天气细节。新增视觉开关有明确旧档默认值。

保存路径仍沿用原工程的 `orbis-demo-v4.json`。**首次打开升级工程前，请备份旧存档。** 分层状态会增加 JSON 的体积和保存/读取成本。事件几何和尚未播放的雷声不是保存对象；读档不会重播历史闪电。

独立数值检查在运行时抽取当前 C# 核心的方程方法体，机械转译为 C++17 后执行。转换保留方程和循环次序；它能检验数值链路，**不能证明 Unity C# 的类型/API 编译正确，也不能证明 GPU 画面正确**。驱动测试使用合成边界条件，不是实际场景的屏幕录制。

已完成 384 柱 × 1,200 步以及 3,456 柱 × 200 步的检查；各自 12 项条件通过。另有 9 项源码接线/资源/兼容检查，以及 11 项原 V4.1.2 大气独立回归检查通过。较长的全分辨率测试触及执行限额，没有记作通过。未验证长时实机稳定性、FPS、显存或移动设备支持。

在 Unity 内可执行：

```text
Tools → ORBIS → V4.2 → 运行天气数值与存档检查
```

## 9. 仍需实机验收的重点

首先确认 Console 没有 C# / Shader 编译错误，然后检验：同一地块在不同时间会经历有云/少云/晴空；低、中、高层云相对位置会变化；湿润对流区能出现发展和成熟阶段；降雨位置与雨滴、水花、湿地一致；雷电只在满足雷暴条件时产生；夜间云不发白；展开地图不把云变成黑色遮片；穿入云层时遮挡连续。

还需要测量完整分辨率的主线程天气成本、3D 纹理上传成本、云影缓存和低分辨率合成的 GPU 成本。当前核心没有接入 Burst/Jobs/Compute Shader。不得把本包作为“已经达到 60 FPS”或“全平台无编译错误”的证据。

目前没有远景体积雨幕、屋内/屋顶防雨、完整积雪粒子、真实电场求解、解析云砧形态、全球能量守恒模式，以及自动迁移外部材质的实现。水量账本覆盖新大气核心和其地表水库，不代表原世界所有土壤、海洋、河流和积雪变量已经统一守恒。
