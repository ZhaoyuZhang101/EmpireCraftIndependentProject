# ORBIS V4.2 · TerrainPerf2 Zone4x4 · Civilization First

本完整包建立在 `V4.2 GreenRingFix TerrainPerf1` 上继续修改，目标从本轮开始明确调整为：**文明模拟与实际游玩优先，全球气候/云/水文/地质属于为文明服务的二级模拟。**

## 本轮主要变化

1. 保留并整合上一轮近海视觉修正、稳定 4×4 Zone 选择、逐 Zone 文明扩张、海岸沙滩/岸浪、地形清晰度与地质手动触发改造。
2. 文明扩张继续以稳定 Zone 为基本领土单位，不再把自然分区直接作为领土吞并单位。
3. 气候核心增加多线程列物理路径：微物理、垂直交换、地表交换、凝结/相变、云诊断按气候柱并行；全球输运、动力边界累积、沉降边缘传播以及闪电 RNG/事件队列仍保持顺序执行，避免共享边写冲突和存档随机序列漂移。
4. 默认并行线程数为 `逻辑处理器数 - 2`（最低 1），主动给文明 AI、主线程、渲染准备和输入留出 CPU 余量。`PlanetSettings.climateWorkerLimit=0` 表示自动；可手工改成 1 强制单线程，或改成指定上限。
5. `OrbisWeather` 运行时调用 `TickParallel()`；气候核心同时保留单线程 `Tick()` 作为确定性参考/验证路径。
6. 当前仍维持每个渲染帧最多执行一个大气固定步的上限，避免追赶天气时把文明主循环拖死。

## 设计优先级

优先级从高到低：

- 文明人口、领土、城市、战争、经济/发展和玩家交互。
- 与文明直接相关的地形、水系、资源和局地天气结果。
- 全球天气的视觉与统计可信度。
- 地质演化、完整全球气候高精度等长期背景模拟。

因此后续即使继续增强气候，也不应以牺牲文明 Tick 稳定性为代价。大气线程默认保留两个逻辑核心给主玩法就是这一原则的第一步。

## 验证状态

已运行 `Validation/validate_terrain_perf2_core.py --resolution 8 --steps 1200`。该测试从当前 C# 方程体机械转换到 C++17 后运行，数值检查通过：有限数值、水平输运水量守恒、云示踪移动/风切变、非对流抬升凝结、夜间风驱蒸发水量闭合以及中纬度凝结不永久为零。

这不是 Unity C# 编译、UnityShaderCompiler、Play Mode 或真实 GPU/CPU 帧率验收。本执行环境没有 Unity Editor，因此完整包仍需要在 Unity 6000.0.47f1 / Built-in Render Pipeline 中打开 `Assets/ORBIS/Scenes/OrbisDemo.unity` 做实机验收。

## 首轮实机验收建议

优先看：

- 拉近海面是否还出现规则菱形/块状视觉伪影；
- 4×4 Zone 点选、领土扩张是否和显示一致；
- 海岸是否出现沙滩、浅水浪花且不会沿三角网格闪烁；
- 运行 10–20 分钟后文明主循环是否比天气线程更稳定；
- Profiler 中主线程是否出现气候突发长帧；
- 欧洲/北美中纬度云是否仍大面积永久空白；
- 夜侧 airglow、月光、弱天光及绿色大气圈修复是否保持。
