# ORBIS 的投影与三层地图

## 结论

这版采用 **Plate Carrée（标准纬线为赤道的等距圆柱投影）** 作为显示坐标：2:1 经纬度矩形、经度周期、纬度有边界。规则 Tile / Zone、寻路、笔刷、存档继续使用原有坐标。

“从平面数据拓扑出球体”可以实现：技术上分成 **地块邻接拓扑**、**经纬度映射**、**显示网格细分** 三件事。经度首尾为相邻列；球体顶点从同一份高度/水面数据求位置。绘图投影本身不负责重新生成地形。

## 为什么没有选另外四种

| 投影 | 特点 | 对本项目的工程判断 |
|---|---|---|
| Plate Carrée | 等间距经纬线组成矩形；极点展开为上下边；高纬形状和面积失真 | 当前规则方格、横向卷轴、GPU UV 与拾取最直接；采用 |
| Mollweide | 等面积、2:1 椭圆边界，极点为点 | 适合面积统计总览；纬度越高横向有效宽度越窄，不能把矩形方格的左右边简单平移平铺 |
| Eckert IV | 等面积，圆弧侧边，极点为短线 | 可作为额外统计地图；仍需非线性逆映射、边缘无效区和显示坐标转换，没有当前玩法的直接收益 |
| Dymaxion | 多面体展开形式，可用于连续大陆的全球展示 | 需要分面邻接、跨面方向变换和展开切口；不适合把普通横向方格卷轴直接当成完整球面邻接 |
| AuthaGraph | 球体经四面体展开为矩形；官方提供连续平铺地图 | **它确实可以平铺，不是“不能无缝”**。但不能等同于现有北向上的经纬度方格；坐标和跨边方向更复杂，且本次未取得可直接接入的官方完整正逆映射实现 |

后四列中的“是否适合 ORBIS”是结合当前代码与玩法的工程判断，不是制图学意义上的优劣排名。Mollweide/Eckert IV 可以日后增加为只读统计视图，不应据此重排权威 Tile ID。

- [Esri：Mollweide](https://doc.esri.com/en/arcgis-pro/latest/help/mapping/properties/mollweide.html)——等面积、椭圆边界和用途。
- [Esri：Eckert IV](https://doc.esri.com/en/arcgis-pro/latest/help/mapping/properties/eckert-iv.html)——等面积、圆弧侧边和极线。

## 同一世界如何对应

令 `u=(x+0.5)/Width`、`v=(y+0.5)/Height`：

```
longitude = 2π(u−0.5)
latitude  = π(v−0.5)
radial    = (cos(latitude) sin(longitude),
             sin(latitude),
            −cos(latitude) cos(longitude))
position  = RotateY(spin) × radial × (1 + height × 0.00001875)
```

球面高度使用原地形，湖海使用同份高度场、岸线与深度计算水面，上限 4000m。显示半径比例有夸张，仅为可读地形；不是声明一个 Tile 有固定真实公里数。东西环绕不复制任何世界数据。

球体到平面：同一网格頂点在球面位置和选定切平面坐标之间插值；颜色、深度使用同一 `ScrollPosition`。体积大气先渐隐，然后混合透视/正交投影。完全展开时换为数学上同一平面的四边形，纹理 UV 保持不变。

二维总览到详细图：相机继续放大，`12–32 px/Tile` 之间混入像素地表与地物，24 px/Tile 切换模式名称。两者没有场景切换，不改选区、路径或数据。像素细节以地图坐标定位，同一个位置在每次环绕和载入后保持一致。

## 必须保留的边界

1. 球面不可能在无切口、无变形的条件下铺成完整平面。这里的“无缝”是操作和数据连续、受控视觉过渡，不是无失真等距展开。
2. 上下极区不能直接首尾相连；当前玩法在纬度边界停止。若未来要角色跨极行走，需增加“越极反射纬度 + 经度偏移半圈”的邻接和相机规则，不能只做 `% Height`。
3. 相同平面 Tile 在球体上的面积并不相同。按球面面积统计时，应使用纬带面积权重；当前经济仍沿用游戏地块规则，没有暗中按纬度改变人口/产量。
4. 当前详细层只是原 Tile 的绘制细节。若未来进入单栋房屋/村民尺度，应建立 `(WorldTileID, localX, localY)` 的局部区块数据和增量存档，并让总览聚合这些数据。不能生成另一份独立小地图而丢失世界对应。
5. 在任意缩放倍率下保留连续操作，意味着过渡中不是严格整数像素缩放。当前未接入会同时改写相机投影的 PixelPerfectCamera。

## 建议的实机性能记录

在 256×128、512×256、1024×512 三个世界中，分别记录球体、展开中间、总览、详细图：CPU/GPU 毫秒、GC Alloc、活动网格顶点、纹理上传和连续生成后的内存。不用合成 GLSL 图的渲染速度推测游戏 FPS。
