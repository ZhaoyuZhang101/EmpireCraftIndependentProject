## 二、数值方法与证据边界

`Validation/validate_v42.py` 从本次交付的 `OrbisAtmosphereCore.cs` 提取方程方法体，机械转换语言语法，使用 g++ C++17 执行。拓扑按原四边形 cube-sphere 算法生成；测试边界条件为合成海陆温度/风，不是实际 Unity 世界的游戏录像。

被测 C# 核心 SHA-256：

```text
95b21debe96dedcb40b67b4bd34f82a7491dbdb41d740e8927cf4e905758c083
```

转译验证覆盖输运、微物理、冷池、对流与电荷的数值路径。它没有编译 C#、执行 JsonUtility、解析 Unity ShaderLab 或调用 Unity 图形/音频 API。这些环节需要随包提供的 Editor 菜单及实机验收。

对全分辨率的独立示踪试验，在 500 次水平输运后：低层云水质心移动 **0.898515 弧度（51.48°）**，高层移动 **1.555829 弧度（89.14°）**。示踪试验特意关闭其他物理过程，仅检查水团输运和分层风差，不是画面 UV 位移。

两组运行的采样记录中，面积加权水量账本最大相对误差约 **1.022e-13**。水量检查包含大气六类水、地表储水、已记账径流及明确外部水源；不能外推为整个旧世界的水/能量守恒证明。样本中水凝物未出现负值，温度保持有限。

384 柱自然实验末端累计 **906** 次气象雷电事件；3,456 柱显式暖湿扰动试验末端累计 **26** 次。全分辨率自然实验 200 步末端雷电计数为 **0**，不能把扰动试验的雷电计数说成该短程自然实验结果。

短程全分辨率的零雷电不被隐藏，也不被当作失败或强制补发：雷暴有发展时间。数值测试产生的事件不等同于已看见闪电折线或已听见雷声。

384 柱水膜干燥孤立测试从 **0.800 mm** 减至 **0.444574 mm**；总水仍留在正确库中。全分辨率对应结果为 **0.447602 mm**。

## 四、12 项数值条件

球面面积闭合；水平输运守恒；云水宏观迁移；分层速度差；带地表及径流的水量闭合；水量非负；温度有限且有界；晴区生云；旧云消散；降雨与地面变湿；孤立微物理守恒；水膜干燥不删除水量。详细中间值见 `validation_384cells.json` 与 `validation_3456cells.json`。

较长的 3,456 柱 × 1,200 步运行触及容器执行限额，未完成；该尝试没有记为通过，不支持长期稳定性结论。游戏画质档位、实际 CPU/GPU 成本也没有由这些数值检查测出。

## 六、重现与真实 Unity 检查

独立测试需要 Python 3、numpy 与 g++：

```bash
python Validation/validate_v42.py 8 1200
python Validation/validate_v42.py 24 200
python Validation/validate_v42_sources.py
python Validation/validate_v412.py
```

前两个命令各自会写最新的 `validation_headless.json`；交付中保留了两组独立命名快照。机械转译代码在临时目录构建，不向 Unity 工程放入可执行二进制。

在 Unity 内执行两个 V4.2 检查菜单。数值菜单会执行真正 C# 的状态演化、正值/预算、分层输运、JsonUtility 存读与继续一致性、非法快照拒绝、无水无雷电负例、旧档开关和时间步约束。Shader 菜单会编译当前后端的 Clouds、CloudShadowCache、AtmosphereComposite、Display、Surface、RiverWater、WeatherParticles 各 Pass。

这些 Editor 检查代码已经提供，但本次未执行。没有生成或冒充它们的 Unity 运行报告。

## 七、人工验收记录模板

使用默认世界与至少一个不同 seed，在自然地貌、文明、展开地图和近地视角分别记录：云是否整体迁移，低中高层是否分离，云影是否跟随，成熟风暴是否有实际降水，雨线是否跟随本地雨强，雨停后水膜是否持续并变干，闪电是否照亮云/地面，雷声是否延迟，暂停/读档/新世界是否残留旧特效。记录 GPU 型号、图形 API、分辨率、云画质档位和帧时间，再决定是否需要降低全球更新频率或迁移到 Jobs/Burst/Compute。

默认包不包含经过这些实机步骤确认的结论。
