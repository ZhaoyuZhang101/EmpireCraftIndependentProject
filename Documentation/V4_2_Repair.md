## 1. 星球转动与定时卡顿

旧的渲染角度依赖离散世界步进及追赶目标；现在把渲染角度放到逐帧 double 时钟，按旋转周期直接推进。世界、文明仍保留原固定步长，不将游戏逻辑改成帧率相关。相机跟随使用这一帧的同一个角度差。

新增可选存档字段 `hasRenderRotation` / `renderRotationDegrees`，旧存档没有字段时仍走兼容路径。暂停不推进自转；读档恢复渲染角而不是重新从零开始。

天气方程从世界的 0.2 秒批处理里拆出来，单个渲染帧最多执行一个 0.1 秒天气步。过载时最多保留 0.8 秒余量，丢弃量记录于 `DroppedSteps`；这是避免追赶风暴的取舍，**不是在任何帧率下都保证完整实时模拟**。天气采样动画用 `Weather.Clock + Accumulator`，在步进边界连续，也遵守天气暂停。

地表颜色从 0.3 秒节奏改成错开天气贴图上传的 0.65 秒节奏；局部 LOD 颜色刷新改为缓存几何、高度和水深，不再逐顶点重跑地形噪声，也不再重复刷新。固定压力梯度、东西方向和风带因子缓存；饱和比湿导数改为解析表达式以减少指数计算。

这些修改针对已定位到的开销和抖动来源，但没有实机 Profiler 证明帧率恢复至某个数字。单次天气步、局部网格重建、首次资源创建仍可能有成本。

## 2. 三条云环、缺少气旋与长期拉丝

原密度式含 `lerp(.08,1.5,structure)`：即使结构噪声为零，只要大范围气候场潮湿，仍存在最低云密度，容易把气候带连成连续环。现在移除非零底值，采用真正可以降到零的体积结构门限，并加入较低频、随风移动的结构变化。天气层决定水凝物是否存在，噪声只细化形状；没有直接画一张永久气旋贴图。

初始化加入六个局部低压扰动和相应南北半球反向切向风，之后交给原有预报式压力、水汽平流、凝结/蒸发与水凝物转换推进。降低过强的风场回归，修正科氏项方向；热力触发不再仅靠整片向阳面的固定抬升项。

细节流采用有界双相位交叉过渡；回溯坐标重投影到原半径球面，避免长期位移累积或径向拉伸。新增周期性 `64³ RGBA8` 噪声：R 是 Perlin-Worley 云体，G 是高频 Worley 侵蚀，B 为辅助 Perlin，A=1。默认直接加载，不在运行中逐帧生成。

**气旋初始化只作用于新生成的世界。** 加载旧 V4-2 世界会保留存档中的风、压力和云水，不强行重置天气；密度、水体、自转、雷电和颜色修复仍生效，但旧有云带要随其天气状态演化，不能承诺读档一瞬间变成新的气旋布局。

这里仍是 12 层降阶游戏气候，不是数值天气预报模式。长期气旋生成、锋面细节及整颗星球的视觉分布需要继续在 Unity 中验收。

## 3. 赤道持续闪电、一直打雷

放电条件要求同一层存在过冷液水、冰与霰的相遇，而不是把不同高度各自存在的成分加起来就触发。加上成熟对流持续时间、CAPE、上升速度、降雨和充电阈值；使用面积缩放的随机触发率，每个单体冷却 22–65 个天气秒。

表现层每帧从队列中选一个可见事件，其他过时事件不追赶播放；全局闪光冷却约 0.70–1.35 个真实秒，音效调度冷却约 8–14 个真实秒。暂停、地图或关闭特效时不累计一堆旧闪电待恢复后播放。缩小闪光空间范围，避免一个电闪照亮整条纬度带。保留原有高度、距离与声音传播延迟处理。

离线 384 格自然场景连续 180 秒天气时间出现 12 个物理放电事件，而不是每帧全带放电。这是该测试种子与边界条件的结果，**不是全球真实闪电频率，也不是 Unity 中实际听到的雷声数量**。

## 6. 近地表水体与白色地表

水体统一用于海洋、湖泊和河流。把表面法线投回切平面，限制坡度，在掠视角淡化扰动，避免着色法线翻到背面。反射方向限制为上半球；GGX 高光加入导数方差粗糙度，减少近景细碎闪烁。折射光程按 Snell 定律计算，掠视角不会简单除以接近零的视线余弦而趋向无限。保留原解析波族，不额外叠加另一套不相关的水面法线。

水深仍来自 V4-2 的河湖/海底代理数据，不是屏幕深度射线重建。**这次不是完整潜水/水下相机功能。** 雨滴表面波纹使用独立周期相位，避免跟随旧短周期时钟产生不匹配的重置。

地表泛白的一条明确路径是积雪：旧代码把 `rain` 显示代理值乘日历天累计成雪，和真实降水率不匹配。现在只按 `SnowRate` 与物理小时换算积累雪，并加入温度融雪；它是显示诊断，不再重复加进物理水库。旧存档暖区异常积雪通过平均温度可见性门控，不再直接染白暖区地貌；真正的寒冷高山和极地仍可以白。

地形图集加载失败时设置 `_TerrainAtlasReady=0` 并保留地貌顶点颜色，不把默认白纹理当作有效地形贴图。没有用整体压暗或统一涂绿掩盖材质问题。

## 8. 本机 Unity 验收顺序

先关闭 Play，运行已有菜单 `Tools/ORBIS/V4.2/強制編譯雲與大氣並輸出報告`，检查 `Documentation/Unity-V4_2-shader-report.json`。该菜单会检查 Clouds 三个 pass、Surface、RiverWater、阴影缓存与合成等 shader；不要把 Python 检查当作替代。

确认自然地形层、正常昼夜、SurfaceDebug=0，再分别检查新世界和旧存档。验证自转/暂停/读档；观察云量空隙与不同高度风向；从轨道穿云下降到海边；检查海面掠视角、河口、湖泊；切换地图再返回；到真实成熟雷暴附近检查闪光/音效冷却与关闭开关。Profiler 同时看 CPU 天气步进、GC 与 GPU 云/阴影开销，保持相同分辨率和质量档与原 V4-2 对照。

若仍出现 `Internal error communicating with the shader compiler process / 0x80000004`，这表示本机编译器进程通信失败；本包不能在没有 Editor.log 的情况下证明进程问题已经消失。此时保留新编译报告与 Editor.log，不要继续堆叠别的版本补丁。源码中的长积分循环保持 rolled，没有把 GLtracy 的 80×8 嵌套采样强制展开。
