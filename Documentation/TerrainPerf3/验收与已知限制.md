## 本机最短验收路径

首先打开Orbis2DWorld并等待脚本导入。在Console中确认没有C#错误，再执行 Tools/ORBIS/2D World/2 Run core data validation。实际结果写入 `Validation/FlatWorld/unity-core-report.json`，会记录Unity版本、断言数量、最后操作与异常。

该C#测试包括20档边界、65组气候用例、Tile/Zone反查、左右循环与南北封闭、固定种子重现、12个月并行结果重现、排水秩、累计径流、文明初始人数、扩张人口转移、路径端点、地形淹没人口保留、完整存档编码往返以及校验码损坏拒绝。这里只列“测试代码覆盖”，不列“这些C#测试均已通过”。

可选的独立.NET验证（需要已安装.NET 8 SDK，不依赖NuGet第三方包）：

```sh
dotnet run --project Validation/FlatWorld/FlatWorld.Core.Tests.csproj
```

Unity无图形的核心批处理（只测试核心，不测试着色器）：

```sh
"<Unity安装路径>/Unity" -batchmode -nographics -quit -projectPath "<项目绝对路径>" -executeMethod Orbis.Editor.FlatWorldEditor.ValidateCoreBatch -logFile "<日志绝对路径>"
```

随后使用带图形的Editor执行第3个着色器菜单，分别检查新地图/路径结果及旧球体着色器报告；不要把无图形批处理当GPU测试。第4个Windows构建菜单依赖对应Build Support模块。

## 已知限制与取舍

新场景是玩法架构原型，文明为聚落级人口与粮食，不包含逐人AI、战争/外交/海军、资源产业链。道路/桥梁影响路径查看，但未实现个体沿路行走。

Zone扩张检查接壤可行走边；若一个Zone内部含互不连接的岛块，尚未缓存每个岛块与首都的连通分量。因此不能声称所有占领Tile都有一条从首都可达的陆路。未来可在Zone之下引入可达性分量，不必改变16格归属结构。

最大的非正高程连通分量自动认作海洋；内陆水体均按淡水处理。盐度、封闭盐湖、水坝/水库、人为指定海盆未实现。排水是地形汇流网络，不是二维浅水方程；气候是合成年循环，不是实时全球天气求解。星球云层为静态月均快照叠加视觉动画，缺少瞬时气旋、阵雨与闪电事件联动。

2D有平移/整数缩放，但只显示一张地图，不渲染无限横向重复地图；逻辑左右循环，南北不循环。极地投影收缩只影响展示。球面几何是有限细分与视觉高度夸张，非真实地球尺寸或每Tile一个独立球面平台。

大地图编辑仍整图重算；摄影初次构建可能卡顿。CPU纹理按脏块整理，但Apply仍可能全纹理上传。性能目标不是已测结果，建议先默认尺寸，实际瓶颈由Profiler确定。

没有撤销/自动保存；生成/导入会替换运行中世界。保存优先用File.Replace；不支持时备份后移动，不保证断电严格原子。高度图只保存地床，水体预览不回读，完整状态请用原生存档。

目标为桌面Built-in管线。没有URP/HDRP迁移、WebGL线程兼容、移动端触摸多指缩放、无障碍或小屏UI完整适配验收。系统字体通过系统接口读取，不随包分发字体文件。
