## 先打开，再验收

将压缩包解压。在 Unity Hub 添加包含 `Assets`、`Packages`、`ProjectSettings` 的文件夹，打开 `Assets/ORBIS/Scenes/OrbisDemo.unity`，等待导入完成后按 Play。

先使用左侧的 **「载入双图范例」**，确认替换。旧世界会先保存到持久化存档目录。然后点击「寻找主河」，切换自然地貌／展开地图，或点击「降落地表」继续滚轮缩放。例图本身在 `Examples/RiverValley/`，可以直接拿它作为自己的绘图模板。

默认选择粒度为「连通区块」。移动鼠标查看青色悬停边框，单击锁定金色轮廓；只显示所选集合的外轮廓，不把内部格子全部描亮。粒度可切换成单一地块、自然区域、连通区块。球面与展开地图共用选择集合，拾取使用地块的实际角点边界进行复核。

## 如何导入自己的高度图和河流图

### 方法一：运行时目录入口

点击「打开导入文件夹」，将图片放入该文件夹：

```text
MapImport/
  heightmap.png
  rivers.png
```

也接受对应 `.bmp` 文件；同名 PNG 优先。界面「地图资料夹」可改为另一个目录。点击「从目录建图」后确认。读取失败、尺寸不符或检测到明显的河道逆坡时不会替换当前世界。图像缺少河流时可按高度自动生成河网。

### 方法二：Unity 编辑器选文件

打开 **Tools → ORBIS → V4 → Heightmap and River Map**。可以分别选择两张图片，并调整海平面灰度和高度跨度。「只校验图像」不需要运行世界；「建立世界」与导出需要 Play Mode。

### 图像约定

使用 **2:1 等经纬图**，建议从 1024×512 开始；最多 2,097,152 像素、每文件 32 MiB。顶部为北，底部为南，横向覆盖 −180° 到 +180°。两张图的裁剪、大小和方向必须完全一致。不能把任意局部 DEM 原样裹成全球。

默认高度换算：

```text
h = (gray16 / 65535 - 0.475) × 2
surfaceRadius = 1 + h × 0.075
```

实际绘制中海洋显示在半径 1 的水面；湖泊另使用其流域水位。`h` 是工程的归一化、视觉夸张高度，不是可直接当作真实米制 DEM 的测地坐标。

高度图建议使用 16 位灰度 PNG，8 位可用但高度层级更少。不要使用 JPEG；不要给数据图加色调映射、sRGB 转换、自动对比度或有损压缩。PNG 支持非交错的灰度、RGB、RGBA、灰度＋Alpha；高度 RGB 必须是灰度。8 位索引 PNG 和未压缩 8 位索引 BMP 可用于河流图。当前不支持 PNG Adam7 交错、BMP RLE、GeoTIFF 或 RAW。

河流图画**单像素中心线**。原生约定：白色、黑色或透明是无河流；蓝色像素表示河流，蓝色亮度给出宽度提示。绿色、红色和黄色标记会保留为连接节点，但**没有声称完整复刻 EU4 的调色板、源点、合流和分汊语义**。宽度由流量与属性共同决定，不是把河面整块涂成蓝色。超过 120,000 个有效河流像素会拒绝导入。

有多个海洋端点的图可以形成多个出口；对环路采用确定性的排水树取向，不是完整分汊流量求解。没有接到海的连通分量以较低的内陆端点结束，不会强制拉到海平面。若地形和河线严重冲突，需要先修改输入图，而不是任由水面悬浮跨山。

### 双图导出和完整保存的区别

「导出双图」创建带时间戳和随机后缀的新目录，包含 `heightmap.png`、`rivers.png` 和说明，不覆盖已有输入。输出灰度统一使用默认 `0.475 / 2` 的约定；即使原图导入时用了其他海平面，也先转回同一归一化高度再输出。

导出的是**当前未做细河床切割的基础地形＋地形编辑量**，不会把已经挖过的细河床重复输入，再挖第二次。程序河网需要栅格化成中心线，所以双图重建存在分辨率损失，不能宣称逐顶点无损。

**两张地图是世界地形模板，不是完整游戏存档。** 国家、人口、外交／战争、时间、视角、天气等仍须使用「保存世界」。V4 完整 JSON 内嵌源图，之后移动原图片不会破坏该存档。导入前的自动备份保存世界状态；其相机状态不等同于正常保存按钮生成的完整视角快照。

## 国家创建和 2D 素材入口

选择陆地区块后按「在选区建国」。只在首府生成 500 初始人口，不会给区块里每一格复制 500 人。土地可保持国家归属而暂时没有居民。

点击一个已有国家的地块，再按「以此国家圈地」。然后选择相邻无主选区，按「纳入相邻选区」。自动区块拓展每 20 个游戏日检查一次；人口不足、邻地被他国占据或地形条件过差时不会拓展。不会以这个按钮代替战争征服规则。

在场景中选中带 `OrbisDemo` 的对象，可在 Inspector 的 **V4 sprite art (optional)** 中指定 `buildingSprite` 和 `personSprite`。当前接口接收整张透明 PNG（Texture2D），不是 SpriteAtlas 的子图配置。默认占位图位于 `Assets/ORBIS/Resources/ORBIS/V4/`，可直接替换；人物会保留图片纵横比。

目前建筑和居民是与聚落数据相连的视觉标记；居民只有轻微动作提示，并不是每个人都拥有独立寻路、工作、战争和动画状态机。已有文明人口、拓荒与远征系统仍在，但不应把本次精灵入口称为完整 WorldBox 人物模拟。

## 当前边界，不夸大

保留 **3,456 个逻辑地块**。导入更清晰的图只提高地形／河流定位表达，不会自动得到同等数量的模拟地块；小于地块的岛屿或河道不具有独立行政单元。

视觉河网遵循导入中心线，河流存在标记参与自然区域与名称选择；粗粒度气候、排水流域和文明仍在原地块图上运行，尚未把高分辨率河网升级成独立的气候／行政网络。

曲线、床高、河宽在地形重建时生成，不是每帧运行完整河流水动力。入海包含水位、宽度和着色过渡，不包含真实泥沙输运、潮汐反馈、三角洲生长或复杂分汊守恒求解。热松弛也不是完整水蚀侵蚀器。

较大的图片和世界重建在主线程同步处理，可能出现等待；未提供性能保证。近景水岸抗锯齿、分支网格交叠、细河流远景可见性和各平台 Shader 编译仍需要实机调校。展开图允许投影变形，游戏逻辑编号没有为地图投影重排。
