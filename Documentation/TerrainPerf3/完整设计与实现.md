# 完整设计与实现：2D 为权威，星球为投影

## 1. 重构边界

输入基础包是 `ORBIS_Unity_V4_2_GreenRingFix_TerrainPerf2_Zone4x4_CivilizationFirst_Full.zip`。保留原始资源、旧场景、大气/水体/夜侧着色器与回归工具；新场景使用独立核心数据。改动清单与基础文件哈希见本目录 `baseline-files.json` 和 `change-manifest.json`。

以前的球面粗网格是 `6×24×24=3456` 条模拟记录；4×4 子格来自选区布局，不能直接声称有 16 个独立居民/地形记录。新布局将平面 Tile 定为唯一身份，Zone 只负责聚合与领地扩张。原粗网格在新摄影模式只做渲染兼容采样，不再是模拟单元。

```
预设/种子/高度图 → WorldData（唯一世界状态）
                      ├→ FlatSimulation（人口/粮食/扩张）
                      ├→ FlatMapRenderer（2D 地图与图层）
                      ├→ FlatSave（完整状态）
                      └→ OrbisFlatSnapshot → OrbisPlanetView（只读星球）
```

这不是同时维护一张 2D 图和一颗独立生成的球。两种视图以同一 Tile ID、同一海拔、水体与归属为源，禁止摄影适配器调用旧 `OrbisWorld.Step`。

## 2. Tile / Zone / Chunk

| 层级 | 作用 | 数据约束 |
|---|---|---|
| Tile | 最小地形和模拟单位 | 矩形格、独立高度/水体/气候/人口/设施/归属 |
| Zone | 文明管理与扩张单位 | 严格 4×4=16 Tile；归属更新同时写入16格 |
| Chunk | CPU 渲染脏块 | 32×32 Tile，仅管理更新，不改变地块身份 |

索引为 `tile = y×Width+x`；`zone = floor(y/4)×(Width/4)+floor(x/4)`。内部 y=0 为南边。经度方向循环，南北不循环；不能从北极瞬移到南极。

默认 512×256，对应 131072 Tiles、8192 Zones。UI 还提供 256×128、1024×512。最大尺寸为数据输入限制，并不是已经通过某台设备帧率验收。2D 单格面积用于公平玩法，不宣称对应球面等面积或固定多少平方公里。

核心采用结构化数组，9 个核心 C# 文件置于无 Unity 引用的 `Orbis.Flat.Core` 程序集。Unity API、纹理创建、场景对象、GUI 都留在主线程。重建任务只操作自己的副本，完成校验后一次性替换可见世界；取消或失败保留旧数据。

## 3. 高度与预设

用户的“20 档，前10档100米、上方逐渐拉大至4000米”按下表解释。区间采用 `(下界,上界]`，0m 是海平面。每一档的可编辑预设高度取其上界，不存在自动把地面重新变成任意连续噪声高度的情况。

海拔、地表生物群系、水体和建筑不能混成一个枚举：同为 100m 可以是雨林、荒漠、河谷或沙滩；不同海拔可以同属一种气候。湖面高度单独保存，不拿湖底当湖面。

## 4. 水体与排水

深海/中海/浅海按海床 −1000m、−200m 两条边界划分。淡水进一步区分 Lake / River。先找最大的连通海平面以下水域作为海洋，其余内陆负高程洼地视为淡水湖。这是无盐度模型的明确游戏假设；封闭盐湖、人工盐海、用户指定海洋连通分量尚未实现。

在海洋根节点上运行优先级填洼，向四邻居扩展。每个新节点指向已经出队的父节点，因此平地也不会形成 A→B→A 环；不通过给高度添加 epsilon 来破坏预设米数。无海地图以最低点作为排水根，南北仍封闭。

`WaterLevel` 保存填洼/溢流高度，**并非每个陆地 Tile 都真实被水覆盖**。湖泊满足水面比地床高至少100m，或是非海洋的非正高程洼地；其他格按累计径流阈值识别河流。累计量是游戏汇流指标，不是标定过的 m³/s。逆拓扑累计使上游来水最终到达根，水量守恒只指这项累计运算，不声称守恒的全球水循环。

海岸沙滩来自水体邻近与低海拔规则，不来自文明颜色。2D 本版水体为像素材质/颜色，不包含物理水波求解或独立海滩浪花模拟；3D 保留基础包的水面视觉。

## 5. 季节气候与 Köppen

采用 Beck 等 2018 年论文 Table 2 的 30 类版本，C/D 分界为0°C，B类优先；月平均温度单位°C，月降水量单位mm。夏冬按4–9月与10–3月两段中较暖/较冷的半年确定，而不是把南半球也硬套北半球季节。来源与具体判据见《开源项目学习对照与来源》。

生成温度考虑纬度、海拔递减、海陆距离、纬向海洋调节项和年温差。生成降水考虑热带辐合带季节位置、中纬度降水带、东西向水汽输送、地形抬升、背风和简化季风。沿纬圈预热两圈、第三圈记录，以降低经度接缝对水汽初值的依赖。

每个纬度行可独立计算，使用 `Parallel.For`，自动最多8个工作线程，并在可行时给其他工作保留2个逻辑核心。没有把 UnityEngine 对象交给后台线程。这里不是 Burst/Jobs 实现，也没有声称实测线程加速比。

Köppen 对12个月气候基准值分类；月份变化读取已存月值，不在一场阵雨后改变气候带。生态映射再结合高程、河流、降水与温度产生沙滩/草地/林地/雨林/荒漠/草原/针叶林/苔原/高山/冰雪/湿地。

**限制**：合成模型不是数值天气预报、海气耦合大循环或多年气候演变。年循环重复，地形变化时显式重算。尚未导入真实月均气候数据，亦未实现基于文明排放的长期气候反馈。30类均有分类用例，不代表每个随机世界一定会出现全部30类。

## 6. 文明循环

首都500人→季节与肥力影响粮食→人口增长/饥饿→选择接壤的无主 Zone→消耗粮食→从已有聚落迁入人口。默认最多12文明，可手工建国或播种。

Zone归属写入全部16格；海水占据的格子仍可属于沿岸Zone，但不能建普通聚落。扩张要求相邻Zone之间存在可行走的共边，不允许跨无连接海洋直接扩张。现在属于宏观聚落人口迁移，**没有逐个小人沿路径走动**。

农田增加季节粮食，道路降低寻路代价，桥梁用于河流或深度不超过100m的浅湖。此100m是原型阈值，不声称为现实桥梁工程条件。设施不能覆盖首都/聚落。路径为四邻居Dijkstra，按需调用，有搜索预算；跨地图左右接缝的路径逻辑有效，但为了不画出穿越整图的长直线，本版只提示其长度。

地形淹没居民时，人口移到该文明待安置人口，再尽可能迁入仍可居住的己方地块。若全境不可居住，保留待安置人口和无首都状态，不把人口无声删除；尚无可视化难民单位。

战争军队、外交、贸易、技术树、海军、详细居民生命史不在本版实现范围。之后应扩展这一2D核心，而不是重新向3D摄影适配器写模拟。

## 7. 2D 渲染与性能边界

用一个矩形网格和每 Tile 一 texel 的数据纹理展示地图，不为每格建立 GameObject/Collider。Point采样、无Mip、禁用相机MSAA/HDR（2D），相机按整数像素对齐。城市/农田/道路的程序化符号在足够近的缩放级别出现。

四张纹理分别为自然地表、当前图层、归属、语义；归属纹理RGB是文明颜色，A为 owner+1 的小整数编码，0为无主。边界比较ID，不比较颜色距离，避免相似颜色文明边界消失。

CPU按32×32脏块更新数组和SetPixels32。**Texture2D.Apply可能仍上传整张纹理；这不是保证只更新GPU子区的实现。**月温/降水图层翻月会全量刷新，自然图层不必每月全部刷新。没有依据源码就承诺帧率提升多少。

模拟单步按天推进，每帧最多补算3次并限制欠账，避免卡顿后无限补帧。宏观文明在主线程，重建生成在后台；主线程只接收完整通过校验的结果。1024档需要比512档更多内存，尚未做移动端验收。

## 8. 星球重建与对应关系

经纬映射：`u=atan2(x,z)/(2π)+0.5`，`v=asin(y)/π+0.5`，对应2D西东和南北。地形作为北在上方的16-bit高度图进入原 `OrbisWorldMap`，采样到基础包已有焊接闭合的球面细分拓扑；不是简单把一张平面截图贴到平滑球上。

地床决定海拔数据，湖面决定湖泊可见表面，海洋表面在海平面。高度经过视觉夸张：本版保留基包的高度比例，而不是1:1地球尺度。球面几何有限分辨率，不保证每个高分辨率Tile都拥有独立几何平台；行政归属和水体纹理仍按原Tile采样。

3D球体不生成新的地形、不调用旧文明Step。适配器只保留3456个渲染兼容采样点，填入月均气候展示数据。切入摄影时暂停2D时钟，保留水/云视觉动画；旧的高频大气求解器不推进。因此保留渲染效果不等于保留新场景里的真实动态云雨模拟。

自然/文明两种显示在球体上支持；高度、柯本、温度等诊断图层目前主要供2D使用，切入球体仍显示自然地表（文明图层除外）。不在高纬重新计算人口面积，避免摄影投影影响玩法公平。

## 9. 文件与后续接口

新原生存档版本1，Magic `ORBIS-FLAT-01`，包含全部Tile字段、12个月气候、Zone归属、人口与文明。最大96MiB；读取校验尺寸、枚举、有限数、排水顺序、相邻关系、人口可居住性、Tile/Zone归属一致与SHA-256。SHA-256用于损坏检测，不作为防篡改签名。

支持平台优先使用File.Replace与备份；降级备份/删除/移动不能保证断电时严格原子，恢复应查 `.bak`。导出高度图与水体预览不是完整存档，预览水体图不参与导入。

地形大改采用整图重建的保守路径。后续优先增加区域重算、归属可达性分量缓存、设施/单位指令、撤销日志；这些列为后续设计，不列为已交付功能。
