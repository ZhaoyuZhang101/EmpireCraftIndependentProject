# 源码审查与修复记录

## 审查口径

按指定TerrainPerf2完整包逐文件构建变更清单，区分原有实现、重构中修复、静态可检查问题及必须进入Unity才能判断的问题。没有将“括号平衡”写成“所有C#编译通过”。本目录旧基础哈希可追踪保留内容。

## 基础实现与迁移风险

| 位置/事项 | 实际观察 | 本分支处理 |
|---|---|---|
| OrbisZoneLayout/旧SphereGrid | 旧4×4主要为选区子格；权威模拟仍是3456条球面记录 | 新WorldData拥有真正的独立矩形Tile数组，Zone聚合16格 |
| 旧展开地图 | 改变展示方式不等于把模拟迁到平面 | 新主场景使用FlatSimulation，不再靠展开旧球面场景充当2D世界 |
| 编辑器首次初始化 | OrbisDemoEditor.FirstOpen会打开旧场景、覆盖构建列表为旧场景 | 改为Orbis2DWorld默认入口，更新初始化键，旧场景单列回归菜单 |
| Windows构建入口 | 原按钮硬编码仅构建OrbisDemo | 改为新2D主场景在先、旧回归场景在后的列表 |
| 两视图文明归属 | 粗采样插值不能精确表示所有新Tile边界 | 共享Owner纹理；A存owner+1，按ID判断边界而非颜色差 |
| 高程语义 | 旧normalized h不能直接当整数米，湖底也不是湖面 | 新核心统一米数；展示适配器显式转换，高度图编码记录范围 |
| 原存档兼容 | 旧ID是球面粗格，与新矩形Tile一一对应关系不存在 | 独立Magic/版本/文件名，不静默迁移或覆盖旧存档 |
| 旧报告 | 包内有多个版本的历史验证报告 | 全部保留但明确不作为本次Unity运行证据 |

这些多数是架构与迁移风险，不全是旧版本语法错误。对原包不能给出“存在X个编译错误”的无依据统计。

## 本次编写过程中已修正的问题

| 风险 | 修正 |
|---|---|
| short海拔与Math.Max整数字面量混用可能导致重载歧义 | 温度/降水海拔表达式显式转int |
| 完全平坦地形中随意选下游会形成环 | 优先队列出队顺序作为DAG秩，父节点总在子节点之前 |
| 把Land/River的填洼高度重置为地床会破坏排水验证 | 保留全图溢流高度；渲染仅在真湖泊使用湖面高度 |
| 淹没首都直接清零人口 | 转待安置人口、尝试移居己方可居住格，否则保留待安置状态 |
| 地形编辑后桥梁悬空或覆盖深海 | 重建时检查河/湖类型和深度，清除失效桥梁 |
| 16-bit高度误差使100m再次导入变200m | 先还原并四舍五入整数米，再查档位；检查0m边界 |
| 扩张创建人口而不是迁移人口 | 从已有聚落扣除并转移，不在16格重复500人 |

| 新纹理/材质失败时先销毁旧世界 | 新显示对象先完整构造，成功后再移除旧对象 |
| 自定义路径材质在构建时被剥离 | Route.shader显式放入Resources并通过Resources.Load使用 |
| 跨经线路径绘制穿越整图的长直线 | 路径逻辑保留，跨缝时不显示误导性的整条LineRenderer |
| 摄影视图误入旧模拟推进 | OrbisWorld.Step对IsPresentationOnly立即拒绝 |
| 截图异常被后续提示覆盖 | 保留截图异常提示，不伪报请求已提交 |

## 已执行检查

`Validation/FlatWorld/static-report.json` 记录全Assets C#/Shader/CGINC/USS的词法结构检查、XML解析、资源字面路径、GUID与主场景一致性。检查器区分#if/#ifdef/#ifndef，避免把合法include guard错当缺失#if。此检查不具备C#类型系统、Unity UXML/USS导入器或HLSL后端。

`classifier-cpp-report.json` 来自实际C#分类函数体的C++17机械转译，65个输入/预期值全部通过。它仅支持分类数值逻辑结论；不能证明托管程序编译、并行代码或Unity API有效。

`reference-world-report.json` 来自独立NumPy参考实现，覆盖4类世界预设、全陆、全海、排水无环、汇流守恒、高程范围、种子重现及高度整数往返。它不是C#执行记录，float64边界与C# float32可能不同。
