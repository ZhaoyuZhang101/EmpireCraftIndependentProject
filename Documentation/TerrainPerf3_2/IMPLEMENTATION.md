# Perf3.2 实现、数据契约与限制

## 1. 基线与权威数据

输入包是 `ORBIS_TerrainPerf3_1_WaterClimate_Full.zip`。在其 Assets 上升级，所有原文件和原 Unity GUID 保留；变更清单记录在本版 manifest。WorldData 继续是唯一权威状态；HeightBands、FlatHydrology、FlatSimulation、FlatSave 不为视觉平滑而另起一套逻辑。

`FlatTerrainFacts` 增加 `Vegetation` 与 `Canopy`；构造和 Clone 均复制这两项。旧序列化 Biome 枚举未扩充。任何平滑和河道曲线都只影响显示及局部水面扰动的可见湿区，不反写作者高度、Zone、归属、人口、路径拓扑或全局水量。渲染字段由地形重建任务计算；Unity 的材质、纹理、GameObject 仍只在主线程操作。

## 2. 水陆连续边界

`FlatSurfaceSampling.DistanceSquared` 用一维抛物线下包络做可分离欧氏距离变换。东西方向取三份周期拷贝的中段，南北不周期连接。海洋和湖泊为面状湿区，窄河流不把整格标为面状水。距离在水陆中心之间减半格，截断到 ±8 Tile。空种子使用有限哨兵，避免全海或全陆出现无穷值。

严格距离直接插值仍可能保留二值边界阶梯，因此本版对该显示场执行两次 3×3 `[1 2 1]` 平滑，最后要求每一个水格中心至少 +0.15、每一个陆格中心至多 −0.15。这样不会因平滑删掉单格岛/单格湖的中心类别。**此后的 ShoreDistance 是受约束的显示场，不再是精确米制或欧氏距离；岸滩厚度是视觉参数。**

采样采用 minmod 斜率限制的三次 Hermite：一维单区间值保持在两个中心端值之间，二维采用 16 样本的可分离重建。U repeat、V clamp；连续的是显示场，不把语义 ID 双线性混合。屏幕空间覆盖用 `fwidth`/像素尺度控制边缘过渡。局部 SWE 的 Coverage 使用同一 CPU 插值和曲线，边缘抗锯齿容差因模拟与屏幕空间不同而有区别。

算法不是“给整个屏幕加模糊”，也不是额外细分模拟 Tile；没有承诺所有局部形状与原二值面积完全相等。水陆类别在格中心保留，但岸线在格内的位置是显示重建结果。

## 3. 河道曲线、汇流与宽度

原 Priority-Flood 和无环排水父子图不变。每个河流格从四边连接位和实际下游方向选择出口。对每条入流，以格边中点为起点、中心为控制点、下游格边中点为终点，构造二次贝塞尔；单连接源头从中心走向连接边。多支流做距离场并集。

CPU/HLSL 都用 8 条弦逼近同一曲线，再扣除插值半宽。控制点位于本格凸包内，不用无约束高阶样条越过相邻山地/不同水域。渲染曲线并不是新的可通航路径或河床侵蚀算法。

半宽为 `clamp(0.07 + 0.07*log2(max(1, runoff/threshold)), 0.07, 0.40)` Tile，其中 runoff 是原游戏汇流代理，不是 m³/s。共同格边采用相邻河段平均半宽；在连接边内 0.10 Tile 的带状区域，把距离和流向收敛到共同的横截面，修复“端点一致但变宽曲线距离场不一致”的细缝。数值回归覆盖不同进/出口及不同宽度的邻接组合，记录边界距离最大分歧为 0（只针对该测试集合）。

实际水面总宽范围为 0.14–0.80 Tile，仍受最小屏幕足迹限制。不能保证每个缩放层级都能辨别最细支流；极近景的 8 段曲线近似也不是无限精度解析曲线。

## 4. 水体光学、海床显示与波纹

保持 Perf3.1 已适配的 HPWater 单段散射/消光与 Schlick 反射代码；河、湖、海与摄影地表共享调用。水深来自静态基准水面减床面以及原河深代理，海床低于海平面的档位不被改写。水深示意把浅水到深水映射到对数颜色段，并从邻近真实深度的连续采样生成海床明暗。这样有助于阅读地形，但**它是增强的制图式表达，不是假定深海真的透明**。

程序水纹沿流向平移，采用错开半周期的双相纹理坐标与连续权重，削弱重复复位接缝；球面周期坐标避免 U 接缝，远景根据导数衰减高频。泡沫基于连续岸场或河边距离，不以每格方框描边。SWE 零扰动法线写为 RG=(128,128)，Shader 按 `(RG*255-128)/127` 解码，消除无扰动仍带偏斜的问题。

原 `FlatShallowWater` 求解核心保持不变：单个可见区 64×64、约 10 Hz、最多一项后台任务，共享面有限体积通量、供体出流限制、自适应 CFL。它围绕静态基准水面求扰动，不承担全世界海洋或洪泛。只有二维近景满足开关/像素阈值时运行，星球不运行局部 SWE。局部窗口跨世界日期变更线的完整连续拼接不是本版新增能力。

关闭水面着色会走廉价蓝色水面分支，仍保留水陆遮罩，而非暴露为了岸边颜色延拓而填入的陆地色。关闭“水深示意”保留光学计算但不加制图色阶；二者用途不同。

## 5. 地表颜色、起伏和等高线

自然底色与类别数据分开：自然图可平滑混合，海边用 2 Tile 的相邻陆色延拓避免蓝色污染岸上；最终水面由覆盖掩码合成。Owner/Info 按中心 Point 采样，诊断图也强制取格中心，不把民族 ID 或 Biome 当作连续数值。文明色只在 Shader 混合一次，去掉原 CPU 与 Shader 双重染色。

新 `_VisualTex` 四通道：R=作者高度(m)，G=平滑岸场，B=水深(m)，A=冠层密度。RGBAHalf 可用时优先，否则 RGBAFloat；均是线性数据，不走 sRGB 解码。旧 HydroA/Geo 与语义字段保留。地表与海床明暗采用更宽的连续邻域梯度，而不是把量化高度平台的导数亮暗逐格显露出来。

等高线采用同一个有界高度重建场，以 100/200/500/1000m 为基本间隔。像素内高度跨度过大时按二次幂增大实际等高距，每五条主线加深；平坦地面、远景、水面减弱或不画。默认关闭。颜色平滑开关只关底色过渡，不恢复已废弃的粗方形岸线。

## 7. 二维环境与摄影

`FlatSkyRenderer` 从同一 WorldData 读取本月和下月雨温，缓存中承载低云、高云亮度与风暴视觉代理；纹理默认 256×128，可选 128×64/512×256，最高 5 Hz。月或地形版本改变时才重新上传气候。云噪声用球面坐标和有界旋转/周期运动，不将上一帧的云无限反复拉伸。暂停保留缓存、不重绘相同画面；不需要环境的诊断层休眠。

二维晨昏与一年 360 天的季节太阳倾角代理共用太阳方向；自动昼夜转动与文明时间分离，120秒一圈。月光、天光、薄雾、夜灯、雨幕与稀疏闪电都是呈现近似，没有创建新的气象状态。云随月气候变化并有真实屏幕位置变化，但不能据此宣称实现了新的三维全球压力/温度耦合云动力学。

摄影仍绑定同样的地形、归属、河湖与视觉字段，并保留原体积云/大气相机路径。云/云影/大气/昼夜开关接到两个入口；二维缓存和原体积云并不保证形状逐像素一致，也没有把月气候贴图重新解释成原三维云的所有物理状态。雨幕和本次新增闪电是二维专用选项。

## 8. Surface 编译路径与降级

原 `Surface.shader` 归档于 `Reference/Perf3_1_Surface.shader.txt`，Unity 不会把它当作 Shader 导入。新版 `SURFACE_LIT_PERF32` 不包含原来的 OrbisOptics/OrbisWater/CloudCommon 重路径，体积大气留给原相机 Pass；静态声明采样器从原路径的 16 个降到 9 个，没有引入关键词笛卡尔积。深度 Pass 独立命名。

**IPC 日志只证明 Unity 与编译器进程通信失败，不能单凭 0x80000004 证明某一函数、采样器溢出或驱动是唯一根因。这里实施的是减轻并隔离问题路径的源码修复；是否消除了用户机器上的崩溃仍须原生验证。** Shader 不支持时显式选用单纹理 `SurfaceFallback`，HUD/Console 显示降级，不把降级当成完整水体/光照效果成功。

轻量 Surface 对历史旧场景保留基础地表/图集兼容；旧 SurfaceDebug 1/2/4 有对应输出，旧 3/5 深层光学/雪诊断不再按原重路径输出。主要受支持入口是 Orbis2DWorld。原 AtmosphereComposite/Clouds 仍在工程中，这不等同本次重新验收了它们的所有变体。

## 9. 实测范围与成本

此次有执行的项目是词法/资源/引用检查、方法体 C++ 转译数值回归、GLSL 片元移植探针及合成数据渲染。GLSL probe 显式去掉 Unity 顶点变换与 patch clipping，软件渲染器为 Mesa llvmpipe；Gamma 图像执行，Linear 分支只做编译。没有原生 C#、Unity Shader Lab/HLSL、D3D11、Play Mode 或 GPU 帧率结果。

有界插值增加片元采样成本；表面采样器减少不代表每个像素都更便宜。使用云缓存、单任务局部水面、地形版本更新、远景细节淡出和功能开关来约束成本。性能应以目标机器的主线程、渲染线程与 GPU frame time 实测，而不是以压缩包大小或软件探针耗时判断。
