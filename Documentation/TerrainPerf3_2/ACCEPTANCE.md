# Perf3.2 本机验收

此清单尚未在本次交付环境执行。完成后保存 Editor.log、`Validation/Perf3_2/unity-native-report.json` 和实际截图，不用包内算法夹具代替。

## 环境与首次导入

把完整工程解压到新目录，不覆盖个人修改。Unity Hub 使用 6000.0.47f1，Built-in 管线；等待导入结束。检查 C# 与 UXML 错误。主场景 `Assets/ORBIS/Scenes/Orbis2DWorld.unity`。

先执行 `Tools → ORBIS → Perf3.2 → Validate continuous world on current GPU API`。该入口跑真正 C# 核心测试、原生 UXML 导入与新控件检查、FlatMap/Surface/Route/FlatSkyBake/SurfaceFallback 的默认 Pass 同步编译。还需要下面的 Play Mode 验收；没有遍历旧云/大气的全部关键词和全部设备。

Windows PowerShell（Unity Editor 路径按本机安装位置填写）：

```powershell
.\Validation\Perf3_2\run_d3d11.ps1 -UnityEditor "C:\Program Files\Unity\Hub\Editor\6000.0.47f1\Editor\Unity.exe"
```

运行时关闭同一工程的另一个 Editor。脚本强制 D3D11，不能添加 `-nographics`，不能用其他图形 API 的 PASS 当作 D3D11 PASS。若进程再次断连，记录 Console 完整上下文与 Editor.log 中报错前的编译信息；检查命名的 `SURFACE_LIT_PERF32` / `SURFACE_DEPTH_PERF32`，不要把“粉红不再显示但用了回退”判为正常完整渲染。

## 画面与操作

| 项目 | 验收动作与通过条件 |
|---|---|
| 原图问题复核 | 加载原 Perf3.1 的 `.orbis` 存档，定位同一海岸/湖泊/河道，以同一缩放截图对比；不以不同种子代替前后比较。 |
| 岸线 | 自然层从总览放大至 8/16/32/64 px/Tile；检查斜岸、凹湾、单格岛/湖、U 接缝和南北边缘；没有原方形粗描边，中心水陆类型仍正确。 |
| 河道 | 定位入海口，上溯检查源头、90度弯道、分支汇合、过格边、入湖和入海；弯道连续、有大小宽度差，邻格共同边不裂，未误绘穿山支路。 |
| 水深 | 笔刷/预设分别包含 −80/−600/−2200m 海床；开关“水深/海底高差示意”，浅海、深海区分变化且没有全海透明；河湖海均保留水面。 |
| 波纹 | 近景启用 SWE 并按扰动；波传播、不出现厚方圈；暂停和恢复不爆炸；远景退回程序波纹；30分钟运行检查拉伸、相位跳变和分配增长。 |
| 等高线 | 启用100/200/500/1000m，放大/缩小高山和平原；应连续且过密变稀，平地不整块涂满，河海水面不画；关闭后完全去掉该叠层。 |
| 植被 | 切到“14类生态植被”读类别，再回自然层；草地/疏林/密林/雪地可辨，近景有细节，关植被细节后底色和数据保留。并非每个随机种子必有14类。 |
| 环境 | 自然/文明层开关低高云、云影、薄雾、透明度与质量；云持续变位置而非无限拉长。数据诊断层不叠云；暂停不继续转动天空。 |
| 晨昏 | 开昼夜、手动改变太阳角；再开120秒自动转光；昼夜应缓慢移动而非跟文明时间每秒闪数次。夜灯只在聚落，雨幕/闪电默认关闭。 |
| 星球 | 往返二维/摄影、缩放/旋转，确认同一地貌、河湖和文明；检查大气/云/昼夜开关；Console/HUD 未显示 fallback 才能算主表面路径通过。 |
| 数据 | 保存旧档副本，载入、选择/扩张4×4Zone、发展文明、编辑地形重建、再保存；确认新植被缓存不改变旧v1字段与世界人口。 |
| 生命周期 | 连续新建/加载/重算、切换视图、改变缓存质量各20次，观察内存/纹理/任务数量，无残留云缓存和重复模拟。 |

## 性能记录

在默认 512×256 和最大 1024×512 分别记录自然层与摄影的主线程/渲染线程/GPU frame time；同时记录显卡、驱动、分辨率、颜色空间、云质量和开启选项。依次关植被、地形明暗、云影、云、水光学与局部SWE，查出成本来源。Shader 的采样器声明更少不代表所有视觉模式都更快。开启诊断层时云缓存应休眠，暂停时不重复绘制相同缓存，近景SWE最多一个后台任务。

如 C# 导入失败，后续菜单不会执行，也不会生成有效 native-report；如原生编译失败，离线回归成功不能覆盖该失败。将失败状态保留下来再修复。
