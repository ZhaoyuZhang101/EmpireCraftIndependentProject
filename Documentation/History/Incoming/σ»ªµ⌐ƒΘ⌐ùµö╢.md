# 在 Unity 檢查新版

這份清單尚未在工作環境執行。請使用 Unity 6 的 Built-in 管線開啟完整專案。

## 啟動

1. 等候第一次匯入，檢查 Console 是否有紅色錯誤。
2. 執行 Tools → ORBIS → 驗證圖形與中文字型。此選單檢查已匯入資源，不取代畫面檢查。
3. 開啟 OrbisDemo，Game 視窗設為 1600×900，按 Play。中文字應完整顯示。

## 這次提出的問題

| 操作 | 應觀察的結果 |
|---|---|
| 自轉開啟，保持視角不動 | 地表與國界、地名一起連續旋轉，沒有五次／秒的跳動。 |
| 拖曳與滾輪，再鬆開 | 相機有短暫阻尼，縮放平滑。 |
| 開啟「跟隨地表」 | 選定一側地表大致保持在視野內，太陽照明仍隨當地時間改變。 |
| 自然圖層放大山脈 | 表面法線連續，近看有山脊、紋理與河谷；Chunk 邊界沒有可見裂縫。 |
| 雲層開、風向開，風力設 0 | 雲平流停止；覆蓋量仍可隨凝結／消散改變。恢復風力後依局部風場移動。 |
| 觀察低壓與暖濕區 | 雲量、雨帶與風向改變；暖濕區可形成較厚雲體。右側顯示氣壓、濕度和雲型。 |
| 雲層關、大氣開、晝夜開 | 可單獨查看日夜分界、晨昏暖色與藍色大氣邊緣。 |
| 大氣關，再開 | 散射和光學透射合成應改變，地面日夜控制仍可獨立使用。 |
| 將雲品質由 32 改成 80 步 | 細節與步進品質改變；記錄幀時間，不預設任何顯卡都能達 60 FPS。 |
| M 切換地圖，查看日期變更線與極區 | 地圖沒有跨整張畫布的三角形或極點缺口；可以平移、縮放與選取。 |

## 模擬與存檔

1. 點「播種四個文明」，以 20 倍速觀察成長。從有足夠人口的地塊派出拓荒隊；版圖上應顯示連續路線與隊伍。
2. 科技達航海時代後檢查跨海路線。開戰才可派遠征軍；停戰後軍團返鄉。
3. 保存含在途隊伍的世界，改變視角、參數和速度後載入，檢查恢復結果。
4. 有舊版 `orbis-demo-v1.json` 時，在沒有 v2 存檔的測試資料夾中驗證遷移。先備份自己的原存檔。
5. Tools → ORBIS → 驗證世界模擬會執行多個種子及長期運行檢查，可能需要等待。
6. 建置 Windows 示範版，測試 Player 的中文字、輸入、保存路徑與 Shader；不要只以 Editor 成功當作建置驗收。

發現錯誤時，保存 Console 的完整錯誤文字、Unity 版本、渲染管線、GPU 型號與截圖，才能區分編譯、資源匯入、數值及顯卡相容性問題。
