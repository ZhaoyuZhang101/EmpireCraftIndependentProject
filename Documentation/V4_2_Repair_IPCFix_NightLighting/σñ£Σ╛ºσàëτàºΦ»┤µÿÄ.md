## 2. 夜侧不再只剩一个接近零的固定补光值

原实现的夜间固定底色很小，且没有月光方向。现在把夜侧光照拆开处理，而不是把 `max(N·L, 0)` 改成一个很大的常量：

```text
地表线性辐亮度 = 材质反照率 ×（原太阳光 + 原晨昏间接光 + 夜间天光 + 月光）
               + 对应的水面／湿地反射 + 原有灯火与闪电

体积源项       = 原太阳散射 + 微弱夜间散射 + 月光散射 + 高空气辉自发光
```

所有新增项进入原有线性 HDR 流程，再由原合成器统一曝光和色调映射。没有改变曝光默认值，没有末端 RGB 最低值钳制。材质应有的深浅、阴影与黑色仍保留；这不承诺洞穴、完全遮蔽处或零反照率表面每个像素都不为零。

### 气辉 airglow

新增高空的弱发光层，源项不再乘太阳直射可见性或太阳能量。它随昼夜权重淡入夜侧，再进入已有前向 Beer 消光积分，因此不是贴在最终画面上的亮边。近地天光同时获得很弱的向下气辉分量。

默认偏淡绿色，仅作为可辨识的夜空气辉，不代表极光系统。太阳散射的原晨昏色保持原有算法，不把气辉颜色混入白天反照率。关闭大气或把空气密度设为零，会关闭气辉与其向下照明。

**尺度限制：**本工程本来就是行星半径 1、大气外半径 1.20 的视觉缩放模型。发光层中心 1.165、宽度 0.016，是为原有采样预算设计的较宽近似，不应解读为真实地球公里高度，也不是高空化学过程求解。

### 月光

运行时计算行星局部坐标的月光方向、可见亮面比例与相位亮度。新月暗、满月亮；游戏第 100 日默认满月。月光不使用太阳阴影图，也不会因为「太阳在行星背面」就被一起清零。使用实际月光方向做行星球体遮挡与大气透射计算。

地表按自身法线接收月光；海洋、湖泊、河流与湿地接入月光漫反射和高光。水面共用原波浪法线、粗糙度与 Fresnel，并增加一个代数 GGX 月光高光项，没有再算一组波浪。云层获得方向性月光和弱漫射照明，厚云比薄云更暗。

**模型限制：**月相周期为游戏历日 29.53 天，使用 Lambert 球相位亮度近似与合成轨道方向，不是现实日期星历、不模拟月球反照率的精细相位效应，也未新增一个可见月球模型或月面贴图。数值亮度是场景线性艺术单位，不是 lux。

### 微弱天光与云下遮挡

无月也保留低强度的冷色环境天光，让露天地形、海面和云层仍能分辨层次。天光对法线方向作半球权重；不以“没晒到太阳”作为把所有间接光都清零的条件。

使用现有 `_Weather` 覆盖度、液态水代理量、`_GroundField` 地表高度与采样高度，估计上方剩余云柱光学厚度。月光经指数衰减；漫射天光保留一个很弱的透射／多次散射近似。不会把厚云下的间接照明强行设成零，也不会直接把厚云涂白。

**遮挡限制：**这是天气柱近似，不是新增的沿月光方向云体积追踪。斜射光被远处横向云团遮挡、山体精确月影、洞穴遮蔽和地形全局光照没有在本次新增。没有新星空纹理；这里实现的是微弱天空照明贡献。

## 3. 默认参数和存档

Play 模式选中挂载 `OrbisPlanetView` 的星球对象，展开 `V4.2 Repair IPC — 夜侧光照（随世界存档）`。可编辑字段如下：

| 字段 | 默认值 | 含义 |
|---|---:|---|
| enabled | true | 本次夜侧光照总开关 |
| skyStrength | 1.0 | 微弱夜间天光倍率 |
| airglowStrength | 1.0 | 高空气辉与很弱的向下照明倍率 |
| fullMoonStrength | 0.12 | 满月照明，场景线性艺术单位 |
| cloudAttenuation | 1.0 | 天光／月光云柱遮挡强度；0 关闭这项遮挡 |
| lunarCycleDays | 29.53 | 游戏历日中的月相周期 |
| phaseAtDay100 | 0.5 | 第 100 日的相位；0 新月、0.5 满月 |
| orbitalInclinationDegrees | 5.1 | 合成月光轨道的倾斜参数 |

需要更暗而不丢失轮廓时，优先把 `skyStrength` 调到 0.7 左右、`fullMoonStrength` 调到 0.08；需要更清楚的夜侧地貌时，先把 `skyStrength` 调到 1.2，而不是抬高全局曝光。这些是未做实机场景验收的美术调参起点，不是实测最佳值。

设置存储在 `PlanetSettings.nightLighting`，沿用存档 v4。旧存档缺少该对象时补默认值；明确保存的 0 不会被当成“缺字段”强行改亮。NaN、无穷值和非法范围在运行时钳制。使用游戏原有保存功能才会写入世界存档；仅退出 Play 不保证保存。

保留原有 `settings.night=true`，即「昼夜」开启。关闭昼夜是旧版的明亮检查模式，不适用于自然夜景验收。球体、地外／近地和展开地图共用这些绑定，不新增另一套不一致的地图月相。

## 4. 保留 IPC 修复，不靠加倍追踪实现月光

`Clouds.shader` 本身未修改，MRT_VOLUME、FULL_RES_VOLUME、MAP_VOLUME 三个 Pass、Shader target 3.5、MRT 输出与合成路径保持原样。原平坦视线循环上限 325、单一云阴影调用点、单一直接阴影回退调用点不变。

新增夜光 include 没有 `for` / `while`，没有 3D 云密度采样，也不在视线循环里再调用一次太阳 8 步回退。月光优先复用与光源方向无关的大气光学厚度 LUT；LUT 尚未准备好时，只用简单代数透射近似。

每个受影响的夜侧采样可能新增天气／地表两次 2D 读取与月光大气 LUT 一次读取，以及少量相位、指数和反射计算。月光相位函数放在每条视线循环之前。**没有额外重型云追踪不等于零成本；真实 GPU 用时和 FPS 尚未测量。**

## 5. 安装与本机验收

已有工程使用 `ORBIS_V4_2_Repair_IPCFix1_NightLighting_Patch.zip`；新建干净副本可直接使用 `ORBIS_Unity_V4_2_Repair_IPCFix1_NightLighting_Full.zip`，二选一。

退出 Unity，备份当前工程。手工安装按补丁目录同名合并，保留原 `.meta`，不要把整个 Assets 删除重建。更建议执行根目录 README 中的 Python 安装器：默认仅预检，`--apply` 才会先备份、后覆盖。它要求与发布的 IPCFix1 源文件指纹一致，遇到自改或其它版本拒绝写入。

完整工程仍使用场景 `Assets/ORBIS/Scenes/OrbisDemo.unity`。打开后先执行菜单：

**Tools → ORBIS → V4.2 Repair → 编译夜侧光照并保存诊断**

该菜单只在手动触发时运行，检查当前 Editor 图形 API 的 10 个默认 Shader Pass，记录源文件 SHA-256、图形后端、Unity 版本与编译日志，并在调用编译器之前落盘检查点。若有 IPC 崩溃，上次成功报告不会冒充这次成功。没有图形设备或不是 Built-in 时明确记录未执行。

本机批处理入口：

```text
Unity -batchmode -projectPath "工程绝对路径" -executeMethod Orbis.Editor.OrbisV42NightLightingValidation.ValidateBatch -logFile "night-lighting-shaders.log"
```

不要加 `-nographics`。本机报告位于本说明同目录 `Unity-compile-report.json`；本交付包没有预先伪造这个报告。

### 画面检查项目

1. 原自然材质模式、昼夜开启：看轨道夜侧、晨昏线、云层内外和展开地图。夜側應仍暗于白天，但能辨认地貌与云的厚薄；不能整片泛白。对照时使用相同种子、相机、曝光和天气。
2. 暂停时对照新月和满月；注意 `phaseAtDay100` 是相位偏移，不保证任意当前历日设成 0.5 就是满月。第 100 日可直接比较 0 和 0.5。查看月光方向变到球体背面时月光消失，而天光和气辉仍在。
3. 看晴空与厚云：云下月光应更弱；海面／河流／湿地的月光高光应来自同一方向，而不是复用太阳高光。夜景不是恒定蓝白平面。
4. 关闭大气：气辉消失，但保留很弱的天外环境照明。保存并重载夜光强度为 0 的设置，确认 0 保留；载入旧存档确认补默认值。
5. 用原质量档检查帧耗、控制台和进出大气路径。编译通过、画面符合预期、性能达标是三个独立验收结论。

仅当怀疑旧 Shader 缓存时，在 Unity 退出状态把存在的 `Library/ShaderCache` 改名备份；不删除整个 Library，也不动 Assets、Packages、ProjectSettings。
