# 帝国盒子玩法核心移植计划

把「帝国盒子」模组的玩法核心(政权、城市、人口、宗族、政体制度、外交战争、帝国天下宗教……)搬进本仓库，跑在 ORBIS 的星球地图上，做成脱离 WorldBox 的独立游戏。

模组仓库：`EmpireCraft`(WorldBox 模组)。本文所列行数以模组提交 `7200168c`(2026-11-18)为准。

## 一、已定的方向

| 事项 | 决定 |
|---|---|
| 仓库 | 独立游戏在本仓库写。模组不原地拆 |
| 带什么过来 | 只搬模组自己写的规则、数值和数据。不搬模组里那套原版替身(`.server/Shim`)、Harmony 补丁、从原版抽出来的表与编号，也不抄原版代码和资源 |
| 架构 | 自己的数据层(实体层)加一组世界操作接口。玩法规则只认自己的实体 |
| 地图归属单位 | 按地块算：城的辖区、国界、战线都以 ORBIS 的单格为单位。默认世界改为 1024×512，一格约 39 公里，陆地约 13 万格 |
| 搬迁顺序 | 先建实体层，再依次搬人口城市、宗族人物、政体制度，然后才是外交战争、帝国天下宗教 |
| 和模组同步 | 只搬已经稳定的模块，每个文件记下它来自模组的哪个提交；模组后来有改动时，按记录比对差异，再补过来 |
| 帧率 | 新机制按自己的规则和数值来写，热路径不在每帧分配内存，月结、年结分帧摊开(帧预算) |

## 二、两边现状

**模组**(依赖清单见模组仓库 `Docs/standalone-decoupling-inventory-2026-11-16.md`)

- 玩法核心约 25.4 万行，引用原版对象 22,821 处。其中政权组织 15,586 处，地图地块 7,365 处，人物 3,590 处。
- 界面 5.3 万行、补丁 2.4 万行，都不搬：界面在新客户端里重写，补丁里挂着的逻辑改成世界操作接口里的直接调用。
- 依赖按难拆的程度分五档：
  - 第 0 档：已经独立，有 218 个系统、2.3 万行，可以整份拷过来；
  - 第 1 档：只拿原版的国、城、人当身份用，换成自己的实体就行；
  - 第 2 档：借用了原版的运行机制(换主、开战、立君、人口生死)；
  - 第 3 档：依赖原版的地图地块；
  - 第 4 档：依赖原版的资产表。
- 规则数据：`InstitutionTrees/*.json`(八套制度树)、`ClaimRules.json`、`ConstitutionTemplates.json`、`IdeologyBureaus.json`、`ReligionTenets.json`、`Technology/`、`Locales/`。都是模组自己的，可以直接带过来。
- `.server/` 独立服务器已经证明：模组核心在纯 .NET 里配上替身就能跑。它是搬迁时的参照，可以从中看出每个系统到底用了原版的哪些东西，但替身本身不搬。

**本仓库**

- `Orbis.Flat.Core`(纯 C#，`noEngineReferences`)已经有：星球格网(2:1，每 4×4 格一个分区)、板块地形、侵蚀、水文、气候(柯本分区、月降水与气温)、地表植被、野生动物和存档。
- 文明部分只有 `FlatSimulation`：最多 12 个 `Nation`，按格记归属(`Owner`)，靠粮食扩张，另有聚落、农田、道路、桥。这一块会被新的实体层取代，ORBIS 的部分不动。
- 测试：`Validation/FlatWorld` 是 dotnet 控制台程序，命令行参数选测试组。Unity 侧有 `OrbisMapCapture` 命令行截图。
- 协作者在 `Assets/ORBIS` 下频繁提交，所以帝国盒子的代码单独放一个目录，尽量不碰 ORBIS 的文件，以免冲突。

## 三、架构

```
Assets/EmpireCraft/
  Core/            EmpireCraft.Core.asmdef(noEngineReferences，引用 Orbis.Flat.Core)
    Entities/      政权 Realm、城 City、人 Person、宗族 Clan、王朝 Dynasty
    World/         EmpireWorld(实体仓库 + 地图视图)、世界操作 WorldOps、历法、随机数、史书日志
    Rules/         第 0 档纯规则(原样搬，只改命名空间)
    Systems/       搬过来的玩法系统(按阶段增加)
    Save/          自己的存档段(带版本号)
  Data/            模组的规则数据 json(制度树、诉求、宪法模板……)
  Presentation/    Unity 侧：国家图层、城标、窗口(后期)
Validation/EmpireCraft/   dotnet 控制台：冒烟、回归、确定性、存读档对账
Port/manifest.json        每个搬过来的文件：模组路径、来源提交、搬迁日期、改动说明
Tools/PortTool/           改写身份引用的脚本 + 「模组自来源提交以来改了什么」的比对
```

**实体层**

- 每类实体用整数编号，存进各自的仓库，删掉的编号不复用。实体只放核心字段，各系统的状态挂在各自的数据表里，沿用模组扩展数据(`GetOrCreate`)的思路。
- 各实体的核心字段：
  - **政权**：名字、颜色、首都、君主、存亡、文化、宗教、宗主、所辖的城。
  - **城**：名字、所在格、辖区格、所属政权、人口。
  - **人**：名字、性别、生年、父母、宗族、所在城、头衔、存亡。人口大头用模组已有的「背景人口 / 虚拟族人」口径，不给每个人都建实体。
  - **宗族**：族长、成员、门第。
- 地图视图：每格的归属(城和政权)放在 EmpireCraft 自己的数组里，再同步写回 ORBIS 的 `WorldData.Owner`，这样现成的地图图层能直接画出来。地形、河流、肥力、气候直接读 ORBIS 的数据。

**世界操作接口**：第 2 档那些「改世界」的动作，统一走这一层，玩法代码只调接口、不直接改字段。

- 城换主、建国、撤国、立君、废君、迁都、人的生死与入城；
- 后期再加：开战、参战、停战、结盟、立教、起计谋。

接口负责维护不变量，例如：一座城只属于一个政权；首都必须是本国的城；死人不能当君主。

**时间与调度**

- 历法：年、月由 ORBIS 的 `Day` 推出来。
- 月结、年结用模组的帧预算思路(FrameJobs，属第 0 档)，分帧摊到多帧去做。
- 每个系统用自己独立的、可确定的随机数流，保证同样的种子跑出同样的世界。

**存档**：帝国盒子的状态单独存一个版本化的段，跟 ORBIS 存档放在同一位置、一起读写，不改协作者的 `FlatSave` 格式。

## 四、搬迁方法(每个系统都按这几步走)

1. 在 `Port/manifest.json` 登记：模组文件路径和当时的模组提交号。
2. 原样拷进来，先改命名空间。
3. 用 PortTool 机械改写身份引用：`Kingdom`→`Realm`、`City`→`City`、`Actor`→`Person`；`isRekt`/`isAlive()` 换成存亡字段，`data.name`/`data.color` 换成名字、颜色字段，`capital`、`king`、`cities` 换成对应字段。剩下的靠编译报错逐个改。
4. 原版的运行机制改成调世界操作接口。原来靠补丁挂上去的逻辑，改成在系统的月结、年结里直接调用。
5. 原版资产表(计谋、法则、铭牌、资源、起名模板)换成本仓库自己的表。用到的条目先做最小集合。
6. 模组 `Tests/` 里原有的回归测试一起搬过来，没有的就补冒烟测试。每一步都要能编译、能跑。
7. 同步：PortTool 列出模组自登记的来源提交以来改过的文件和差异，按需补过来，再更新来源提交号。

## 五、分阶段

每个阶段完成后都要做到：能编译，`Validation/EmpireCraft` 的冒烟和回归测试全过，同一种子跑两次结果一致，存档读回来对得上。

### 阶段 0：骨架与实体层(第一步，范围小，但能完整跑通)

- 建 `EmpireCraft.Core` 程序集和 `Validation/EmpireCraft` 测试程序。
- 实体层(政权、城、人、宗族)、地图视图(按格归属，同步写回 ORBIS 的 `Owner`)、历法、随机数、史书日志。
- 世界操作接口：建城、城换主、建国、撤国、立君、迁都、出生、死亡。
- 开局：在 ORBIS 世界里按可居住度挑城址(用现成的 `Habitable`、肥力、河流、海岸距离)，建 N 座城和 M 个政权。
- 先用最简规则让世界转起来(这些规则到阶段 2、3 会被搬来的系统替换掉)：
  - 人口按肥力增长；
  - 君主老死后由子嗣继承，没有子嗣就从宗族里选；
  - 城的辖区按距离慢慢长。
- 冒烟测试 `--empire-smoke`：在 1024×512 世界上跑 200 年。检查四件事：不变量始终成立；同种子跑两次逐字段一致；存档读回来一致；每年的模拟耗时在预算内。
- 默认世界大小改为 1024×512。要先确认生成耗时(目前 7～10 秒)可以接受，必要时先优化侵蚀。
- Unity：只把政权归属接到现成的国家图层上，用 `OrbisMapCapture` 出一张疆域图。国家上限 12 个的限制要先放开，或者改成 EmpireCraft 自己的图层。

### 阶段 1：第 0 档纯规则与数据

搬那些不碰原版对象的规则和数据类(先逐个核实确实独立)，每项都配上单元测试：

- **人口与财政**：CityStabilityMath/Rules、PopulationSettlementRules、TreasuryRules；
- **官制与王朝**：OfficialRankRules、DynasticCycleRules、PeerageSuccessionRules；
- **朝堂与诉求**：ClaimRules、ClaimTuning、CourtIssues、CourtDoctrine、CourtCrisisRules；
- **制度与政党**：InstitutionRules、InstitutionDefinitionRegistry、InstitutionConfig、PartyOpeningRules；
- **调度**：帧预算 FrameJobs；
- **规则数据**：制度树等 json 一起带过来。

### 阶段 2：人口与城市(约 6.5 千行)

- CityPopulationSystem(3,121)、CityStabilitySystem(692)、RuralSettlementSystem(903)、LandEconomySystem(1,188)、TreasurySystem 与 TreasuryHoardSystem(共 529)、RealisticAgeSystem(444)。
- 粮食和肥力改用 ORBIS 的气候、水文、地表数据，城的辖区按地块算。
- Unity：疆域图层、城标、点城看城的基本信息(做成最简的面板)。

### 阶段 3：宗族与人物(约 5 千行)

- VirtualGenealogySystem(1,594)、ClanSystem(2,041)、ClanBranchSystem(405)、PrehistoricClanSystem(283)。
- 继承相关：SuccessionLawSystem、SuccessionCouncilSystem(506)、HaremSuccessionSystem、ConstitutionalSuccessionSystem。
- 名人(Talent)、人物故事；人物逻辑连虚拟族人一起数(KinRoster)。

### 阶段 4：政体与制度(约 1.6 万行)

- InstitutionSystem 一族(约 4.4 千行)、CourtSystem 一族(约 2.3 千行)。
- 官职：OfficeSystem、OfficeSelector、OfficialRankSystem。
- 诉求与决议：Claim 系列、DecisionSystem、DecisionScale。
- 共和与议会：RepublicSystem(1,466)、议会与政党(约 3.9 千行)。
- DynasticCycleSystem。

### 阶段 5：外交与战争

- 世界操作接口补上开战、参战、停战、结盟、附庸。
- 先搬战争目标(WarGoalSystem、WarObjective)、议和台(PeaceTable)、叛乱、附庸。
- 再搬军团与战线(Warfare，约 1.55 万行)：分区推进改成按地块，接上 ORBIS 的寻路，过河和翻山的规则用 ORBIS 的河流和地形数据。
- 无人区、道路、关城、长城归在这一阶段，或放到阶段 7。

### 阶段 6：帝国、天下与宗教

- Empire 本体与天下、法理、周制、统一、帝国分治。
- 神圣罗马(HolyRoman)、教廷(Papacy)、伊斯兰分裂、游牧(草原、劫掠联盟、汉化)。

### 阶段 7：剧本与地图导入

- WorldMap 与剧本(约 1.5 万行)：把真实世界地图、预设剧本落到 ORBIS 格网上。
- 网页版剧本编辑器改成输出本仓库的格式。

### 阶段 8：客户端

- Unity 只负责画面和操作：按模组「卷册」宽窗的设计语言重写各个窗口。
- 手机终端网页沿用，接本仓库的核心。

### 阶段 9：收尾

- 原版资产表全部换成自己的表：计谋、法则、元类型、铭牌、意见、特质、资源、起名库。

## 六、规模与帧率目标(阶段 0 时实测后再定)

- 世界：1024×512 格，几百座城、几十个政权，在世的要人上千，其余人口用背景数字记。
- 预算：每一帧里，帝国盒子模拟占用的时间有上限，月结、年结不能造成可感知的卡顿。核心与画面分开，以后可以放在后台线程上跑。
- 热路径(每月、每年遍历所有格子或所有城的循环)用数组存储、不分配内存，同时测出每年的模拟耗时。

## 七、进度量尺

- `Port/manifest.json` 里已搬的文件数和行数，对照模组玩法核心的 25.4 万行。
- 各阶段的测试组数和断言数。
- 和模组的同步滞后：已搬的文件里，模组之后又改过、还没补过来的有多少个。

## 八、风险

- **协作者冲突**：ORBIS 那边更新很频繁。帝国盒子的代码放在 `Assets/EmpireCraft` 下，ORBIS 的文件只做必要的小改动(例如放开国家上限、把世界默认宽度改为 1024)，每次提交前先 rebase。
- **1024 世界的耗时**：生成目前要 7～10 秒，水文、气候的月结也会变成原来的四倍，阶段 0 先实测。
- **概念对不上**：模组里很多规则按 WorldBox 的尺度写死了数值(一个分区 8×8 格、城的大小、行军速度)，换到星球尺度要逐项重定。所有改过的数值都在 `Port/manifest.json` 里注明。
- **人口口径**：模组正在把人物逻辑改成连虚拟族人一起数，搬的时候以模组最新的口径为准。
