# ORBIS Unity V3 MERGED — 大气、近地观察与气候输运

交付日期：2026-09-11。合并来源：本次上传的 `ORBIS_Unity_Demo(1).zip` 与原 `ORBIS_Unity_Demo_v2_CloudWater.zip`。

**这是已写入源码的独立 V3 整合工程，不是编译完成的游戏。当前环境没有连通 Unity Editor；没有执行 Unity 导入、C# / Shader 编译、Play Mode、GPU 性能测试或 Windows 构建。已执行的 13 组离线检查全部通过，范围见 `Documentation/Validation-V3.json`。**

## 1. 打开工程

将压缩包解压到一个**新的目录**，不要覆盖原 V2，也不要把整个工程文件夹拖入另一项目的 Assets。Unity Hub 添加包含 `Assets`、`Packages`、`ProjectSettings` 的 `ORBIS_Unity_V3_Merged` 文件夹。优先使用两份源工程记录的 **Unity 6000.0.47f1，Built-in Render Pipeline**。

打开 `Assets/ORBIS/Scenes/OrbisDemo.unity`，等待本机完成导入，查看 Console，切到 Game 后按 Play。相机、地球、局部地形、大气、输运轨迹与中文界面由原有 bootstrap 自动创建，不需要手动逐个挂组件。也保留 `Tools → ORBIS → 開啟示範場景`。

两份输入工程均没有提交锁定的 `Packages/manifest.json`；本版沿用其 `Packages/README.md` 和原有包配置策略，没有添加第三方 UPM 依赖，也没有在未连接 Editor 的情况下手填包版本。首次打开的引擎模块解析**尚未验证**。已有能运行的 V2 工程可作为本机包配置参考，但不要把其整套旧脚本叠加进 V3。

不要切换 URP/HDRP：当前大气用 Built-in `OnRenderImage`，不是 SRP Renderer Feature。不要把旧 `OrbisCloudRenderer.cs` 或旧版 `Clouds.shader` 再复制回来，它们会与合并后的路径冲突。

## 2. 操作

先在 Game 视窗内点一下地表，让视窗取得键盘焦点。

| 操作 | 本版行为 |
|---|---|
| 鼠标拖曳 | 球体环绕；近地时降低角速度；展开地图时平移 |
| 滚轮 | 按离地高度进行指数缩放，连续经过轨道、大气、云层、地表近景 |
| 降落地表 | 在真实球面上进入当前/选中区域的近景，不是放大平面地图 |
| 重設視角 | 返回整体星球观察 |
| M / 展開地圖 | 全景地图切换；返回时恢复地理关注点，地图中更改选区则进入新选区 |
| F | 聚焦所选逻辑地块 |
| G / 局部格線 | 显示局部切平面规划参考线；不创建新模拟地块 |
| 空格 | 暂停/继续世界与视觉时钟 |
| H | 收合界面面板 |
| 輸運觀測 | 关闭 / 切向风场 / 水汽输运 / 海洋流向 |
| 近地細分 | 对比局部高密度显示网格与原有全球地形 |
| 動態天氣 | 冻结/恢复云水输运与细节流动；不等同暂停整个世界气候和自转 |
| 雲內散射、V2 水體 | 切换各自的新增着色分支 |
| 全解析度對照 | 跳过低分辨率体积缓冲，用全分辨率射线积分检查边缘与 UV 方向 |

高度使用星球基准半径 `R`，不是米或公里。普通缩放范围约 0.003R–5.5R，地表快捷视角约 0.025R。相机靠近已生成聚落时增加安全高度，HUD 显示的是目标离地高度；不代表真人身高或可步行的第一人称视角。

## 4. 地块拉伸与低清：本版解决到哪一层

把“全球模拟单元”和“近地显示顶点”分开。原来的 **3,456 个 cube-sphere 逻辑地块及相邻关系不变**，文明归属、地形编辑、河流、选择和存档仍以它们为依据。显示层不再需要为每个逻辑格子硬画一张矩形色块。

接近地表时，在视线中心建立局部切平面坐标，再把细分顶点投回同一颗球、采样同一份高度与地形细节。近景采取径向正视，避免继续放大全景经纬图；自然地形材质采用连续混合与三平面采样。近地格线是局部空间中的均匀规划参考线。

| 体积/近景画质档 | 局部网格细分 | 单个局部网格顶点数 |
|---|---:|---:|
| 低 | 48 × 48 | 2,401 |
| 中 | 64 × 64 | 4,225 |
| 高 | 96 × 96 | 9,409 |
| 最高 | 128 × 128 | 16,641 |

局部网格在自然地貌/文明版图图层、约 0.19R 以下启用；地理诊断图层仍可显示原地块。网格按离地高度改变覆盖范围，并随关注点重新锚定。颜色与深度 pass 使用同一份互补遮罩，避免两层同时填满同一个交接像素。实际交接边缘是否稳定仍需 GPU 验收。

**没有把整颗球改造成处处等面积、等边长的完美正方形网格。** 正视镜头可以减轻透视压缩，但不能消除球面到平面的全部几何畸变。局部投影只在关注点附近近似保持形状；范围越大，畸变仍会增加。

**新增参考格线不是可独立放置建筑或计算人口的微型逻辑格子。** 本版尚未改成新的六边形/Voronoi/局部微地块游戏拓扑，也没有新增跨块建筑系统。保留旧逻辑是为了不破坏文明、河流、寻路与存档关系。进一步细化实际建造格，需要独立的稳定局部格编号和跨区映射，而不能只加线条。

现有地形 atlas 被保留并提高近景使用方式，没有凭空添加摄影测量资源；细分也不会自动产生比源模拟更精确的地质数据。河流几何沿用上传包逻辑；海洋/湖泊/河流共享着色不代表完整流体求解、真实几何海浪或水下折射。

## 5. 大气与参考着色器

`OrbisAtmosphereCommon.cginc` 按 Dimev 的说明模型独立编写 HLSL 积分：Rayleigh、Mie、臭氧吸收、太阳方向的光学衰减、地球遮光与场景深度截断。原作者的解释和公开代码见：

- https://github.com/Dimev/atmospheric-scattering-explained
- https://github.com/Dimev/atmospheric-scattering-explained/blob/main/atmosphere.glsl

这里不是逐行移植原作者整份 GLSL。空气与云在同一条射线上按实际相交区间排序，颜色和 RGB 透射率共同积累，最后按 `scene × T + L` 合成；避免先后叠两张不理解彼此位置的半透明球壳。云内多次散射保留 V2 的 HP-inspired 简化近似，不是完整 HDRP HanPi 实现。

为适合小型游戏星球，空气壳顶为 1.20R，云底/云顶约 1.085R/1.132R，尺度经过夸张，**不是按地球真实公里数标定的大气**。空气部分也没有完成高阶多次散射 LUT 或科学辐射传输验证。

另外两个链接 `MdGBWG`、`lslXDr` 本次访问受到 robots/HTTP 402 等限制，未取得完整源码和许可。**没有声称已移植这两份 Shader。** 它们列为待核对的用户参考，不把名字或授权臆测为已知；新输运轨迹是独立实现。原 V2 水体中已有的 `MdXyzX` 是另外一项参考，不能与这两个 ID 混为一谈。

授权与归属见 `Documentation/ThirdPartyNotices.md`；现有工程和资源的整体商用许可未在本次重新审计。

## 6. 天气与输运的边界

水汽与云水由相邻球面方向插值输运，凝结、蒸发和降水改变状态。细节相位有界，细节年龄限定在约 ±6 秒，不再把局部速度乘以无限增长的总时间。风暴函数和水波相位也按各自周期收敛。

局部水汽/云水转化有收支对应，但半拉格朗日输运不是严格全局质量守恒的有限体积方法。模型没有完整垂直大气层、真实动力学压力单位或数值预报精度。HUD 的降水与风速明确显示游戏量。

输运视图提供 256 条有限寿命轨迹；风与水汽读取云水输运使用的切向风，洋流读取原有海流场。水汽模式颜色/透明度使用水汽含量乘风强度的代理，不是物理 kg/s 通量。云层会遮挡位于其中的诊断线；需要纯诊断图时可关闭云层。没有声称完成屏幕空间 LIC 或原 Shadertoy 的逐像素复现。

## 7. 存档

新文件为 `orbis-demo-v3.json`，位于 Unity 的 `Application.persistentDataPath`。产品/公司名沿用原工程以便找到旧目录。加载顺序为 V3 → V2 → V1，只在前一文件不存在时寻找后一文件；保留原有备份和错误提示路径，不写回旧 V1/V2 文件。

两份旧分支都使用 version=2，但只有原云水 V2 含天气时钟/云水字段。迁移器用字段识别分支：原云水 V2 保留可用天气库；上传包则从其气候/风暴状态初始化新库。V3 增加 `ORBIS_V3_MERGED` 来源标记，并保存天气时钟、余步、相机高度和视觉时钟。

迁移路径已写入；本次没有收到真实用户存档样本，也没有在 Unity 执行 JsonUtility 回归。不要把源码存在解释为所有历史存档已实测兼容。跨模型升级后的未来天气不会与旧版本逐帧相同。

## 8. 验证与性能

已执行：`python Validation/validate_v3.py`，依赖 Python、NumPy、SciPy。13 组离线检查通过，涵盖源码结构、资源引用、UXML 名称、GUID、球面插值、局部水分收支、有限相位、球壳射线分段、RGB 积分、局部投影、交接遮罩与相机高度。

这些不是 Unity Test Runner 结果；Python float64 参考误差不是 GPU float32 精度保证。详细实测指标见 `Documentation/Validation-V3.json`。

本机进入 Unity 后可执行 `Tools → ORBIS → V3 → 驗證核心與存檔`、`驗證著色器與資源`，并在 Play Mode 执行 `檢查目前近景` 与 `切換全解析度大氣對照`。本版提供了这些测试入口，**没有在交付环境执行它们**。

画质较低时只降低体积缓冲，不缩小地表源图；全分辨率对照用于诊断，不保证更快。不同 API 下的 UV 上下翻转、深度边缘、云内近景、地形交接、暂停保存恢复与性能需要实测。完整验收步骤在 `Documentation/TEST_REPORT.md`。

脚本里的目标帧率 60 只是帧率上限设置，不是测得的 FPS。未实现时域重投影/TAA、行星四叉树流式加载、浮动原点、大尺度多人同步或步行角色。当前目标是单位缩放行星、单目、桌面透视相机；URP/HDRP、XR 和移动端性能不在已验证范围。
