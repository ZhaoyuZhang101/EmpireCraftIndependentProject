## 二、V4 源码实际存在的问题

| 项目 | 源码证据 | 本次处理 |
|---|---|---|
| 黑色／零颜色被替换成白色 | `Surface.shader` 将近零 RGB 改为 `float4(1,1,1,0)` | 移除该兜底，保留合法黑色；显式设置可见 Pass 的 ForwardBase 标记 |
| 地表与大气的日照模型分离 | 地表主要使用法线点积和固定环境亮度，没有共用大气太阳透射率 | 地表、水面直射光接入共享 RGB 太阳透射率；云影仅衰减直射，不乘暗整个环境项 |
| 太阳遮挡边界误判 | `OrbisSunVisible` 原来沿太阳方向偏移起点，再要求入射交点严格大于零；背光地表起点可落进球体而被判成无遮挡 | 改为径向向外偏移，内部点明确遮挡，零入射交点也判遮挡 |
| 展开模式不是同一条云渲染链 | `OnRenderImage` 遇正交相机会直接跳过体积积分；`Atlas.Sync` 没有更新云材质 | 新增经纬度径向大气柱 Pass，在地图模式也同步太阳、天气、噪声和云参数 |
| 云底／背光云间接光被硬切掉 | 云的微弱环境补光乘上 `OrbisSunVisible` | 将间接天空补光与直射可见性分开，并抑制稀薄区域不适用的漫射近似 |
| 云影没有参与空气散射 | 原有 `OrbisCloudShadow` 只用于地表和水面 | 新增共享光学深度图集，空气散射源项实际采样云影，提供云隙光路径 |
| 风向开关不等于动态输运视图 | `showWind/showCurrents` 主要控制静态箭头，动态轨迹另由默认关闭的 `transportView` 控制 | 默认跟随两个开关，支持风和洋流同时显示；增强轨迹、预填尾迹、球面中点积分、前进后海岸检查 |
| 地图／球体显示变换不同 | 旧体积合成包含固定 tone mapping，跳过体积时没有同一显示处理 | 新增共享曝光和最终显示变换，显式处理 Gamma／Linear 与输出 sRGB 状态 |

**这些是源码可证实的问题，不等于已复现你屏幕上每一种“全白”和“黑云”现象。**
V4 也会按模拟积雪量把地表染白：`snow/30` 达到 1 时，雪色遮罩已满。这次没有清空积雪、强行修改气候或把全部地表硬改成绿色；新增诊断用来区分真实积雪、原始底色与光照问题。

## 三、这次接入的渲染关系

```text
实际天气状态 + 有界风相位 + 同一个 3D 噪声
                 │
              云密度函数
                 │
        朝向太阳的八深度光学厚度图集
                 │
         ┌───────┼────────┐
      地表直射   云自阴影   空气散射源项
         │                 │
      云影投射          云隙光／明暗空气柱
         └─────────┬───────┘
       RGB 透射率 × 场景辐亮度 + 体积散射
                   │
             一次最终曝光／显示变换
```

这里借鉴的是 HDRP 的共享 Beer 阴影架构，不是拷贝整个 HDRP。新图集按太阳局部坐标分成八个光学深度层，每层使用同一组积分节点，避免不同深度单独采样引起厚度反向跳变。跨过远侧云壳的特殊光路使用直接积分回退。

局限必须区分：这不是 HDRP 的完整级联阴影、RenderGraph、时域重投影或生产级降噪系统。当前是单星球、单目相机方案。大气高度与散射系数是游戏尺度，没有做真实地球参数标定；天空间接光也是可控近似，极弱夜间补光用于可读性，并非月光模拟。

展开地图采用“每个经纬度上方的大气柱”语义，共用球面太阳和天气。它不是把整个球面天空透视投影铺平；云隙光的空间光柱主要应在球体／近地视角验收。地图外留白不参与云层积分。

## 五、进入场景后怎么对照

在现有面板中找“地表光照诊断”。“原始底色”只看调色板颜色、不参与大气合成；“积雪遮罩”中白色表示雪色权重高，不是照明强。“太阳透射率”用于检查夜面遮挡与晨昏偏色；“云影透射率”白色代表无遮挡、暗色代表太阳被云削弱。诊断结束切回“最终渲染”。

新增“云隙光”“展开图云层”“显示曝光”“云影强度”。默认曝光 1、云影强度 0.8、云隙光与地图云层开启。关闭“昼夜”仍是便于观察地表的检查模式，不代表物理夜景。

“输运观察”默认“跟随风向／洋流开关”：打开“风场流线”或“洋流流线”就有对应轨迹，同时打开可看两者。选择专门的切向风场／水汽／海流项目则覆盖自动选择。轨迹沿真实模拟字段积分，不会主动编造所有洋盆均有闭合环流；是否出现涡旋由速度场决定。风场／洋流专题图层也会自动启用相应轨迹，且不被自然景观云层挡住。

建议的实际验收顺序：固定同一世界与视角，先关云检查白昼／夜面地表；再开云和云影检查陆海阴影位置；随后在近地晨昏视角切换云隙光；最后切展开地图，对照同一经纬度的云团与昼夜区。半分辨率边缘异常时切“全解析度对照”，这是诊断入口，不是“已经解决了所有平台 UV 差异”的保证。

## 六、三维噪声工具怎么使用

上游说明的已验证环境是 Unity 2022.3.62f1、DX11、HDRP；不能把它当作 Unity 6 / Built-in / Metal 已验证兼容。因此本工程只接它输出的数据。

在工具中导出 **RGB 或 RGBA、8 位 PNG 连续切片**，R 通道为云体、G 通道为侵蚀细节。放进仅包含这一组切片的文件夹，文件名最后一组数字应连续，例如 `slice_000.png`、`slice_001.png`。每张宽高 2–256，张数 2–256；不要混入截图。切片方向、周期接缝和噪声统计仍需目视检查。

停止 Play，执行 Unity 菜单：

`Tools > ORBIS > V4.1 > 匯入雲噪聲 PNG 切片`

生成资源：

`Assets/ORBIS/Resources/ORBIS/CloudNoiseExternal.asset`

下一次 Play 自动使用。移出 Resources 或移除该可选资源后，恢复内部周期 32³ 噪声。已有外部纹理不会被运行时 Dispose 销毁；替换前会弹出确认。当前桥接不支持 16 位 PNG、EXR 或 DDS，也不自动下载 DirectXTex；不保证所有导出设置都与现有密度阈值匹配。
