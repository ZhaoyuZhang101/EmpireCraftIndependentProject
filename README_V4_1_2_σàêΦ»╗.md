# ORBIS V4.1.2 — 使用上传 GLSL 的连续大气穿越

**这次是真正的渲染接入，不是仅保存参考。** `atmosphere.glsl` 的密度、Rayleigh／Cornette–Shanks Mie 相位、吸收和双光路透射计算已改写为活动 HLSL，接入原有球体、全分辨率和展开地图渲染入口。

**交付状态：源码集成版。已完成独立数值检查及光学核心的 GLSL ES 软件渲染执行；没有启动 Unity Editor，没有确认 C#／HLSL 编译、Play 画面或硬件帧率。** 不把独立预览当成 Unity 实机截图。

## 打开与操作

完整工程解压到新目录，在 Unity Hub 添加含 `Assets`、`Packages`、`ProjectSettings` 的目录。目标保持 **Unity 6000.0.47f1 / Built-in Render Pipeline**。打开：

`Assets/ORBIS/Scenes/OrbisDemo.unity`

导入完成后先检查 Console，再按 Play。在原有界面中找新增的四个按钮和仰俯角滑块：

| 控件 | 实际行为 |
|---|---|
| 进入大气 | 在当前观察地点平滑下降到地形上方 0.006R，仰俯角转至 82°，接近地平线方向。 |
| 返回太空 | 平滑升至地形上方 2.65R，恢复俯视。 |
| 穿越演示 | 约 30 秒：从当前视角下降 12 秒、近地停留 4 秒、返回轨道 14 秒。不是切换场景或播放视频。 |
| 晨昏视角 | 只把观察者移到当前晨昏线附近，并朝向实际太阳；不修改世界时间、气候或文明。 |
| 仰俯角 | 0° 为径向俯视，90° 为当地切线方向，超过 90° 仰望天空，范围 0–110°。 |

滚轮继续控制高度，拖动仍沿星球观察。滚轮、拖动、改仰俯角或切地图会中断自动演示。旧“降落地表”和主页操作仍能回到传统俯视。相机保持原有地形高度查询与近裁剪设置，不新增贴地步行控制器。

这些按钮会进入自然地貌、打开大气并关闭诊断颜色；保留当前世界、天气及云开关。没有云的天气不会被强行制造成满天云。要明确观察穿云，可在原有天气条件下选择有云地区。

## GLSL 具体用在哪里

实际 HLSL 文件为：

`Assets/ORBIS/Resources/ORBIS/OrbisAtmosphereGLSL.cginc`

`OrbisOptics.cginc` 包含并调用它。`OrbisAtmosphereCommon.cginc` 使用其相位、源项、积分区间和稳定透射合成；地表和河海水面也通过共享光学入口使用同一个太阳透射率。`Reference/atmosphere.glsl` 仍保存上传原文，但不是唯一接入点。

太空视角从射线进入大气的位置开始积分；相机进入大气后从相机处开始。真实深度裁掉被地形挡住的部分，球体求交补充阻止穿过星球。云和空气的消光相加后统一积累，不再叠第二层蓝色罩子。太阳圆盘先作为远处背景，再经过相同透射率与最终曝光。

具体移植对应、参数变化和没有移植的内容见 `Documentation/GLSL-Port-V4_1_2.md`。

## 独立预览页

打开 `Preview/AtmosphereTransit.html`。它不依赖网络资源；光学核心由本次活动 HLSL 机械转换为 GLSL ES。球体地形、云密度和云光照是用于观察光学的简化演示，不是 Unity 原世界。

支持 WebGL 2 时可操作进出、晨昏、高度、视角、太阳和曝光。手机附件查看器等环境可能不提供 WebGL 2；此时会明确显示三张静态离线渲染，按钮可切换太空／近地／晨昏，不伪装成可交互 3D。当前浏览器环境只验证了这一静态回退和界面布局，未成功建立浏览器 WebGL 上下文。

## 在已有 V4.1.1 上应用增量包

先关闭 Unity，把增量包解压到工程外。运行：

```bash
python apply_patch.py --project "你的V4.1.1工程根目录"
python apply_patch.py --project "你的V4.1.1工程根目录" --apply
```

第一条只预检。文件经过 SHA-256 验证，遇到本地改动、缺失基线或路径冲突会停止，没有强制覆盖开关。第二条才应用并备份到工程 `.orbis-backups`。不要直接将补丁 Payload 拖进修改过的项目。此补丁基线是 **V4.1.1**，不是 V4.1；不确定基线时使用完整包另建副本。

## Unity 中必须完成的检查

执行菜单：

`Tools > ORBIS > V4.1.2 > 強制編譯雲與大氣並輸出報告`

实际执行后才生成 `Documentation/Unity-V4_1_2-shader-report.json`。它请求当前 Editor 图形 API 的同步 Pass 编译，并收集编译消息；不是所有关键字、所有设备、所有渲染结果的认证。本包没有预置“Unity 已通过”的报告。

随后对照球体／全分辨率／地图三条路径：太空看星球轮廓；下降穿过 1.20R 大气顶、1.132R 云顶、1.085R 云底；近地切 0°、82°、90°、110°；检查晨昏、夜面、地形遮挡；返回太空并切地图，确认同一地点的日照与云场对应。半分辨率边缘异常时使用已有全分辨率对照，而不是仅凭 Console 没报错认定画面正确。

## 验证与限制

新增离线检查 **11 组通过、0 组失败**；V4.1.1 检查重跑 **9 组通过**。原 V4.1 检查为 **16 组通过、1 组失败**：失败项要求旧的内联源码字符串，现在源项被拆成函数；该断言没有被删掉或悄悄改成通过，新的共享渲染检查覆盖了云影仍乘在空气源项上的连接。历史数学检查不能证明新 Shader 已运行。

另用 Mesa llvmpipe 的 OpenGL ES 3.2 编译、执行了机械转译的光学核心：200 个太阳透射样本、100 个密度样本、101 个相位样本，最大 float32／float64 绝对误差约 **4.41×10⁻⁶**。独立预览也实际生成了太空、近地、晨昏图像。这是软件渲染和数学核对，不是 Unity HLSL 或硬件 GPU 验证。

保留原始场景、已有 meta GUID、地形／天气／河网／区域主体、示例地图、云噪声和 V4.1.1 循环修复。不附带字体文件，沿用系统字体。保存中新增相机仰俯／朝向，旧存档缺字段时按 0° 俯视处理；旧存档实际加载仍需在 Unity 验收。

当前采用 **游戏比例大气**：星球半径 1R，大气顶 1.20R，云层 1.085–1.132R。R 不是真实海拔公里；并未把整个世界改成真实地球尺寸。尚未实现完整多重散射大气、LUT、时域重投影、立体相机或 URP/HDRP 接口。透明且不写深度的物体不由本效果单独补遮挡。

默认是较明显的近地薄雾／远景消光。要调节，在 Play 时找到 `OrbisPlanetView` 组件的 `Atmosphere Profile`：`solarRadiance` 控制空气散射强度，`mieHeightStretch` 与既有气溶胶设置控制近地灰白雾感，`ozoneStrength` 影响吸收。运行时 Inspector 调节不会自动写成新的世界存档配置。
